Device & File I/O Operations
The device and file I/O statements are intended to send data to or from selected devices and files. These statements do not assume a default input or output device; each statement must specify which file or device the data is to come from (enter), or go to (output).
For example:
   enter "Test_Results"; A, B, C
reads data from file Test_Results and stores it in variables A, B, and C.
In a similar fashion,
   output "Print_file"; A, B, C
sends the contents of variables A, B, and C to the file Print_file.
File Identifiers and @<name>s
Because a device is a part of the file system, files and devices are both addressed by a file identifier (a <file id>). This is shown in the preceding examples. However, addressing a file (device) by its identifier is not necessarily the best way to make the access.
When an I/O statement addresses a file (device) by its <file id> the file opens for the access but then closes when the access is completed. Each time the file is addressed, the access starts at the beginning of the file. This method of addressing is acceptable provided that you do not wish to make successive, serial accesses. When you are accessing files from the keyboard—to save programs, for example—the single access is all that is required. The requirement in a program is more likely to be for serial accesses.
Also, it is likely that you will want exclusive control over the file (device) for the duration of the program, to prevent other users in the system from interfering with your program. This can be achieved by assigning the file an @<name> (pronounced at‑name), and then addressing the file by its @<name> instead of by its normal identifier.
When a file or device is assigned an @<name> (by the assign to statement), the file is opened for accessing, and remains open until the @<name> is cancelled. Successive accesses to the file or device are then serial, with the next access starting where the previous access stopped. When you open the file, you specify whether you want to read or write to it, and whether you want exclusive use—i.e., no one else can access it until you close it—or shared use.
If you are writing to it, you also specify whether you want a new file, or whether you want to write over, or append to, an existing file. over means that the existing data in the file is lost, and append retains the existing data and adds the new data at the bottom of the file. The statements in Example 5-2 open a file, sequentially write to it twice, and then close it (the asterisk cancels the @<name>).
Example 5-2 Example of opening a file and writing to the file
   assign @Notes to "/test/board/notes";write,over,exclusive
   output @Notes: A,B,C
   output @Notes: Q,R,X
   assign @Notes to *        ! closes the file
 
If you are assigning an @<name> to a device that you need to write to and read from, then you can specify a read‑and‑write option. This is used with instruments like voltmeters, which you first program to take a measurement and then read the data from. The example in Example 5-3 opens a digital voltmeter, programs it, triggers it to take a reading, reads the result into variable Dvm_reading, and then closes the voltmeter.
Example 5-3 Example of programming a DVM
   assign @DVM to "/dev/dvm1";read, write, exclusive
   output @DVM;"D0 Z0 FL0 T4 F3 1STI 1STN .1STD M0 R5"
   trigger @DVM
   enter @DVM; Dvm_reading
   assign @DVM to *
 
If a disk file—that is, not a device—is opened for read‑and‑write, the first I/O statement to access the file determines whether the type of operation is read or write. Subsequent accesses must be of the same type, until the @<name> is cancelled and the file can be reopened.
Having the file opened for multiple accesses is faster than having to open it and then close it for each access. As long as the file is open, the system knows where the file is and can access it directly, instead of having to search the disk for it. As a rule of thumb, you should use @<name>'s when accessing files and devices from a program. Using file identifiers, while useful when you are operating interactively from the keyboard, has only limited use in a program.
