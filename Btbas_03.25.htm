Nesting Subroutines
Nesting subroutines is different from nesting loops: When two loops are nested, the program lines of the second loop are physically located within the first loop. During execution, when the second loop is encountered, execution of the first is suspended while the second loop is executed; then execution of the first loop is resumed.
Subroutines must be written separately; program lines from one subroutine cannot be located inside another subroutine. To nest subroutines, a call statement can be placed in one subroutine to call another subroutine. The result is that the subroutines are executed in the same way as the nested loops, as described above. When the call is encountered, execution of the first subroutine is suspended while the second is executed; then execution of the first subroutine resumes.
During execution, subroutines can be nested to any depth; one subroutine can call a second subroutine, which can call a third, and so on. Program control is transferred to each successively nested subroutine as it is called; when the exit is made from a nested subroutine, program control returns to the subroutine which called that nested subroutine. Thus exits are made on a last in, first out basis, until control finally returns to the original calling point in the main program.
When nesting subroutines to multiple depths, calls and exits can be interspersed; that is, it is not necessary to make all of the exits back to the main program before making another call. (Notice that this does not change the statement made above that exits are made on a last in, first out basis.) Subroutines cannot be executed recursively: that is, a subroutine cannot call itself, and it cannot be called by another subroutine which is nested in it (for example, subroutine A calls subroutine B, which calls subroutine C, which calls subroutine A, etc.).
