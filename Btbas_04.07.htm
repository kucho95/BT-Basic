Buffered Reporting
A feature called buffered reporting can be used when reporting failures immediately would greatly increase the time required to test a board (such as when the test yield is low). Buffered reporting, which is enabled or disabled by the buffered reporting on/off statement, stores failure data in an internal buffer during testing. After the tests have been completed, the data is sent to the default report device.
Example 5-1 shows an example of buffered reporting.
Example 5-1 Example of buffered reporting
   buffered reporting on       ! Enable buffered reporting.
   save failures on
     !
   log is *                    ! Disable the log device.
   log level is failures
     !
   report is *                 ! Disable the report device.
   report level is report
     !
   Test:
      test "analog/r1"
      test "analog/r2"
      test "analog/r3"
      test "analog/r4"
      test "analog/r5"
      test "analog/c1"
     !
   if boardfailed then
      probe failures
      log out "LOGFILE_B" & val$(I); append
                               ! Send log data to a file.
      report out "REPFILE_B" & val$(I); append
                               ! Send report data to a file.
   end if
     !
   buffered reporting off      ! Disable buffered reporting.
 
In Example 5-1, a report out statement sends the report data to a file. If it is desirable to simply discard the contents of the report buffer, a report clear statement could be used.
Buffered reporting is also useful when testing multi-board panels. When multiple board states (board number is statement) are in effect, multiple buffers are maintained: one log buffer and one report buffer for each board on the panel.
