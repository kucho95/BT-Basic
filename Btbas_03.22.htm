Local Parameters
The local parameters are the variables (and @<name>'s) named in the body of the subroutine, but not in global statements. Local variables can be accessed only as long as the subroutine is running: they cease to exist once the exit is made from that subroutine. Local arrays must be dimensioned (dim statement) in the subroutine; so each time the subroutine is called, they are dimensioned as if for the first time.
Local @<name>'s are similar to local variables; the referenced file remains open only while the subroutine is running. When the exit occurs, if the file is still open it closes automatically.
Any labels used in the subroutine are also local, except for the actual name of the subroutine, which must be unique. Therefore, any given line label can appear in any number of subroutines (and in the main program). These labels cannot interfere with each other since a branch (goto) in one subroutine cannot go to a label in another subroutine, or to a label in the main program.
Example 4-13 contains an example of a subroutine which uses a local variable. Each time an error occurs, the subroutine determines if the STOP key was pressed, or if a runtime error occurred, and prints the appropriate message. In this subroutine, variable Stop_Key is local.
Example 4-13 Example of a subroutine that uses a local variable
   ! Main program
     . . .
   on error call Error_Message
     . . .
   end
 
   sub Error_Message
      Stop_Key = 248       ! the error number if STOP was pressed
      if errn = Stop_Key then
         print datetime$; ": STOP key pressed."
      else
         print datetime$; " Runtime error "; errn
      end if
   subend
 
If a subroutine calls another subroutine, then the calling subroutine can pass its local variables to the called subroutine.
