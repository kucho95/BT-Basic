I/O Statements
I/O statements are a subset of BT-Basic that allows sequential input and output of data to and from files and devices. I/O statements can be grouped into two overall categories:
• Simple I/O, which is recommended for beginners, and serves two purposes:
• Reading data from, and writing data to, the system default input and output devices.
• Reporting test data to the workstation report device.
• Device and File I/O, which is used for more sophisticated applications because it allows greater control than Simple I/O.
The Device and File I/O statements are used to read from, and write to, devices and files other than the defaults. Each time one of these statements is executed, you must specify the selected device or file.
The data to be input or output by the I/O statements can be formatted in either of two ways: free‑field format or imaged format. Free‑field formatting is easier because the system does most of the formatting and you have only minimum control. With imaged formatting, you have complete control over the format but you must specify your requirements in greater detail.
Some of the I/O statements are specifically used for free-field formatting and others are used for imaged formatting. I/O statements which have the secondary keyword using, such as print using, cause imaged formatting. The others, print, for example, cause free‑field formatting.

Table 5-3 contains a brief description of each I/O statement, arranged in alphabetical order.
 
Table 5-3 I/O statements 
Statement
Description
assign to
Assigns an @<name> (pronounced at‑name) to a file or device and opens it. Use of the @<name> enables successive accesses to the file to be made serially (see File Identifiers and @<name>s). Note that devices (like RS-232 ports) are a part of the file system, and are accessed as if they were files.
buffer$
Returns a string containing the last record entered by an enter, input, enter using or input using statement.
buffered reporting on/off
Enables and disables the internal buffering of report data.
enter
Inputs data from files and devices, using free‑field format.
enter using
Same as enter but uses imaged format.
image
Contains formatting specifications for the I/O statements which send or receive data using imaged format.
input
Inputs data from the default input device using free‑field format.
input using
Same as input but uses imaged format.
keyboard is
Changes the default input device, which at login is the workstation's keyboard.
output
Outputs data to files and devices, using free‑field format.
output using
Same as output but uses imaged format.
print
Sends data to the default output device, using free‑field format.
print using
Same as print but uses imaged format.
printer is
Changes the default output device, which at login is the workstation's screen.
report
(BT-Basic) Sends data to the default report device using free‑field format. Note that there is also a report (SHORTS) statement.
report clear
Discards the contents of the report buffer for the current board.
report is
Changes the default report device, which at login is report is * (discards report output).
report level is
Selectively directs failure messages to the report device, the log buffer, both the report device and the log buffer, or discards the failure messages.
report out
Used with buffered reporting; sends the current contents of the report buffer to a device or to a file.
report using
Same as report but uses imaged format.
rli$
Returns a string equal to the current report level.
tab
The tab function is a parameter that can be used in the (free‑field) list of a print, output or report statement. It causes the next field to start at the specified column.
Another set of statements, called datalogging statements, write to files in either free‑field or imaged format. These statements typically begin with the keyword log; for example, log using. See Quality Control Tools > Datalogging for a description of the datalogging statements.
