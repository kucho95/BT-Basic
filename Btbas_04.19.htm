Outputting Data in Imaged Format
Imaged formatting requires that you specify what format each data item is to have. The formatting specifications can appear either in a separate image statement, or they can be included in the I/O statement itself, preceding the list of data.
Notice that the statements which require image specifications can be easily recognized since they contain the keyword using. Thus, print uses free‑field format, and print using uses imaged format.
In Example 5-14, the first line contains an image statement, in this case named Form1. The print using statement references the image statement by its name. The specifications in the image statement determine how the items in the print list will be formatted and the length of each field. Each specification is matched with a corresponding item in the print list. The meaning of the characters used in this example's image specifications are:
• Each a represents one space for a string character
• Each d represents one space for a numeric character
• The period in dd.d shows the placement of the decimal point
Example 5-14 Example of an image statement
   Form1: image aaaaaa, ddd, aaaaaaaa, ddd, aaaaaaa, dd.d
   A = 45 \ B = 7
   print using Form1; "Passed", A, "  Failed", B, "  Ratio", A/B
 
     ! prints   Passed 45  Failed  7  Ratio 6.4
     !          ‑‑‑‑‑>‑‑>‑‑‑‑‑‑‑>‑‑>‑‑‑‑‑‑>‑‑‑>
 
In the image statement it is not necessary to type all the characters in a repetitive string—a repeat factor can be used. A repeat factor is a number indicating the number of times a character is represented (thus aaaaa, 5a and 3aaa are equivalent). Following are two (of many equivalent) ways that the image statement shown above could be typed.
   Form1: image 6a, 3d, 8a, 3d, 7a, 2d.d
   Form1: image 6a, ddd, 4aaaaa, 3d, 7a, dd.d
If a group of specifications are to be repeated, they can be enclosed in parentheses and repeated as a group. This is referred to as replication. The group is preceded by a repeat factor to indicate the number of times the group is to be executed. The image statements in Example 5-15 are equivalent.
Example 5-15 Example of equivalent image statements
   F2 : image 3(8a, 3d), aaaa
   F2 : image 8a, 3d, 8a, 3d, 8a, 3d, aaaa
   A = 45 | B = 7
   print using F2;"Passed", A, "  Failed", B, "   Ratio", A/B, " END"
     ! prints   Passed   45  Failed  7   Ratio  6 END
     !          ‑‑‑‑‑‑‑>‑‑>‑‑‑‑‑‑‑>‑‑>‑‑‑‑‑‑‑>‑‑>‑‑‑>
     !  (Notice that since "Passed" has only 6 characters, it is
     !  left‑justified in its field)
 
There are two main types of image specifications: field specifications, and control specifications. A field specification is used to format a data item (string or numeric) as in the above examples. The control specifications format the overall output or input—adding spaces, linefeeds, text, etc.
Instead of including spaces in the strings in the print list, the spaces can be indicated by an x control specification in the image statement, with each x representing one character space. Using the same values as above for variables A and B, the example in Example 5-16 gives the same output as in Example 5-15.
Example 5-16 Example using control specifications
   A = 45 | B = 7
   F3 : image 6a, xx, 3d, xx, 6a, 3d, 3x, 5a, 3d, x, 3a
   print using F3; "Passed", A, "Failed", B, "Ratio", A/B, "END"
     ! prints   Passed   45  Failed  7   Ratio  6 END
     !          ‑‑‑‑‑>‑>‑‑>‑>‑‑‑‑‑>‑‑>‑‑>‑‑‑‑>‑‑>>‑‑>
     !(spaces)        xx   xx         xxx        x   
 
Notice that a field specification has a corresponding data item in the print list, but a control specification does not. The order in which the items are output is the same as the order of the specifications in the image statement. An item from the print statement is not output until its corresponding field specification is encountered, but a control specification is output as soon as it is encountered.
It is also possible to include text as a control specification in the image statement, instead of as a string in the print list. See Example 5-17.
Example 5-17 Example of including text as a control specification
   A = 45 | B = 7
   F4 : image "Passed", 2x, 3d, 2x, "Failed", 3d, 3x, 5a, 3d, " END"
   print using F4; A, B, "Ratio", A/B
     ! prints   Passed   45  Failed  7   Ratio  6 END
     !          ‑‑‑‑‑>‑>‑‑>‑>‑‑‑‑‑>‑‑>‑‑>‑‑‑‑>‑‑>‑‑‑>
 
(If you have trouble following this example, remember that a control specification—in this case, text and x's—is output as soon as it is encountered).
If the I/O statement contains more items than there are field specifications in the image statement, then the image statement is (automatically) repeated as often as necessary until all of the data has been output. See Example 5-18.
Example 5-18 Example of the I/O statement containing more items than there are field specifications
   Form2 : image 6a, xx, ddd
   A = 45 | B = 7
   print using Form2; "Passed",A, "Failed", B
     ! prints   Passed   45Failed    7
     !          ‑‑‑‑‑>‑>‑‑>‑‑‑‑‑>‑>‑‑>
 
It is also possible to have finished outputting the data from the I/O statement, but still have some unprocessed image specifications. In this case any remaining control specifications will be processed, but any field specifications will be ignored. See Example 5-19.
Example 5-19 Example of unprocessed image specifications
   Ast: image 6a, x, 5d, x, "Test"
   print using Ast; "Analog"
     ! prints   Analog  Test
     !          ‑‑‑6‑>>>‑4‑>
     ! (spaces)       xx    
     ! Since no numeric data was supplied to the print using statement, the "5d" spec
     ! is ignored.
 
When all the data has been output (including any control outputs from the image), an automatic EOL (End Of Line) is sent. The EOL can be suppressed if the output is to a GPIB or an RS‑232 device or to the display; see the <inhibit EOL spec> in the image statement for details. Since the system does not necessarily know what termination sequence a device on the bus or at the RS‑232 port requires, the ability to optionally suppress the EOL enables you to send the appropriate sequence if necessary.
Example 5-20 Example of <inhibit EOL sepc>
print using "6a,#";"123456"
print using "3a";"789"
   ! prints:   123456789
