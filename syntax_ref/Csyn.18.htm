check wait at event (VCL)
Title: HARDWARE WAIT IN A TIMING SET
(Mux systems only)
The check wait at event function appears in a timing set to indicate at which event number in that set a hardware wait is to occur. At the start of the wait, the wait lines are checked to determine if the trigger states specified in a wait terminated when function are set. If the states are not set, the wait lines are then checked on every subsequent TCLK until the states are received. There is then a delay of approximately 550 ns before the test resumes, at the event number following the event at which the wait started. If the specified states are already met when the wait starts, then the wait lasts for approximately 550 ns.
During the wait, all drivers hold their current states, except the DUT clock, if any, which continues to run.
If other activities are scheduled for the same event as the wait, those activities occur at the end of the wait. Any offsets (positive or negative) applied to those activities, are also implemented with respect to the end of the wait.
Syntax
   check wait at event <event#>
   check wait at event <event#> offset <time>
      <event#> is an <integer constant>
      <time> is a <numeric constant>
Parameters
<event#>
The number of the event where the wait is to start. The wait can start on any event in the timing set except the last event.
<time>
The offset, in seconds to be applied to the checks on the wait lines. The value can range from –30 ns to 100 ns.
Examples
  ! in the Declaration section
        . . .
     assign Go to pins 5
     wait line Go
     wait terminated when Go is "1"
        . . .
  ! in the Timing section
        . . .
     timing set T1 is 12 events
           at event 0 set Strobe1 to "1"
           drive vector at event 4
           at event 7 set Strobe1 to "0"
        check wait at event 8   ! after the wait, the test resumes at event 8
           receive vector at event 11
     end timing set
General Information
If waits are used in a VCL test, there should be a test time function in the Declaration section of that test because the SAFEGUARD safety analysis routines cannot know how long a wait lasts.
