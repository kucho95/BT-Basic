Identifier (id)
The term identifier (id) is used in a general sense to imply a reference to a language element. There is no fixed syntax for all ids. In many cases the id is simply the same as the referenced element's name. For instance, the id of a simple variable is the name of that variable. Here are some examples; notice that these ids each contain a label (defined below):
• A - id of a numeric variable called A
• Test - id of a numeric variable called test
• Alpha$ - id of a string variable called Alpha$
The id of an array element consists of the id of the array together with information describing the position of that element within the array. In a 10‑by‑10 array named Scores, for example, the id for the element in row 3, column 6 is Scores(3,6), assuming that both the rows and the columns are numbered 1 through 10.
In other cases, the term id implies more than just a name: it implies whatever is necessary at that time to represent that name. As an example, consider the file identifier for a file named test_data.
Many statements show a <file id> as one (or more) of their parameters; in each case the syntax indicates that the <file id> must be a string expression. Thus the identifier can be the file's name enclosed in quotation marks, as in:
  "test_data"
Alternatively, the identifier can be a string variable which contains the file's id; for example:
  Test$
(This example assumes that variable Test$ contains the string test_data.)
Furthermore, since the <file id> is a string expression, it could be a concatenation of strings and string variables which together make up that file's name. In all of these cases, the <file id> is never quite the same as the file's name, but the id always represents that name.
The id for a file is further complicated by the fact that, because of the hierarchical nature of the file structure, just the file name is not always sufficient to uniquely identify a file. If the working directory (mass storage is statement) contains the name for that file, then just the file name is sufficient for the id. But if another directory is the working directory, then the id must list all the directories (directory ids) in the path from the current directory up to (and including) the directory containing the file name. For example, to get file test_data when it is listed in the working directory, requires just the file name, as in
  get "test_data"
To get the file when it is not in the working directory requires a path description as well as the file name. For example (using arbitrary names):
  get "/production/voltmeters/test_data"
In summary, in the syntax descriptions, the term id (identifier) means whatever is needed at that point to identify a specific element. The syntax will identify the type of element to be referenced (for example, <file id>, <image id>) and will indicate the form that the id can take (for example, <label>, <string expression>). In the case of variables, since the name and the id are usually the same, the syntax simply shows <variable> instead of <variable id>; however, the parameter descriptions will indicate that an id is required.
