unit (VCL)
Title: START DIGITAL UNIT
The unit function is used in the Vector Execution section of a VCL test to mark the start of a digital unit; the end unit function marks the end of the unit. Each test must contain at least one unit, unless the test is a setup‑only test (see Vector Control Language (VCL) in Digital Testing). The units contain the statements to execute the vectors.
The purpose of the unit is to divide the test into small segments so that the program generators can tailor the test to suit the board topology. For a sequential device (i.e., it has memory), the program generators will discard a complete unit if that unit contains any vector execution statements which conflict with the topology of the device as it is connected to the PC board. For a combinatorial device, the program generators normally discard only the individual execution statements with conflicts; however, they will discard the complete unit if there is a conflict and the unit has a tied function.
To ensure that the program generators do not discard more of a test than necessary, each unit should test only a small part of the device. The vectors which the unit executes should manipulate only the pins needed to test that part of the device; the other pins can be allowed to go to their default states. The program generators will then discard that unit only if it has a topology conflict on pins which are critical to that unit.
Each unit should be independent of all other units in the test. That is, the vectors which it executes should not rely (for keeps and toggles) on states established by vectors executed in another unit, in case the program generators should discard that other unit. The first vectors executed in a unit should reset the device, or, if necessary, home it to a known state by a homing loop.
Syntax
  unit
  unit <unit id>
     <unit id> is a <string constant>
Parameters
 
<unit id>
The identifier of the unit. Since it is a string, this parameter can be any length and can contain any printable characters, including spaces. The identifier is not required, but it helps you to identify the unit when you are editing the program. Also, if the program generators discard that unit, they will print the identifier in the test summary report.
Example
  unit "Testing Preset Line of the Flip‑Flop"
     execute Clear_high
     execute Preset_low
     execute Testpreset
  end unit
        unit "Testing Clear Line of the Flip‑Flop"
           execute Clear_low
           execute Preset_high
           execute Testclear
        end unit
