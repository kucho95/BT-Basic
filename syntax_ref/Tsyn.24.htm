test time (VCL)
Title: LIMIT THE TIME A VCL TEST CAN RUN
The test time statement enables you to estimate the time that the test will normally run. This time is used by the SAFEGUARD safety analysis routines as data to be considered when setting the test time-out. The test time statement affects only the test which contains it.
The statement can be used in any test. But it is required if the test has time-undeterministic functions (loops, pauses, etc., whose execution time cannot be determined). The safety analysis routines calculate a normal test time (based on certain assumptions about the time undeterministic functions), and a safe test time. The safe time is the maximum time the test can run without damaging overdriven, upstream devices. It then compares these times to the time specified in the test time statement to determine the time-out for the test. Time-undeterministic statements are:
• at event wait
• continue analog
• homingloop (uncounted)
• pause
If you do not know the test time, then you can specify any value and learn the time later, using the digital debug routines (see Debugging Digital Tests). Alternatively, when the test is compiled, the safety analysis routines calculate the minimum possible runtime and include it in the compiler summary listing. You can then edit the test and use the calculated value as the basis for specifying the proper test time.
If you plan on learning the test time, and you do include the test time statement, then make sure that the time you specify is long enough. If the specified time is too short, time-out will occur before the test run is completed; so that you will not be able to learn its actual run time.
Syntax
  test time <time>
     <time> is a <numeric constant>
Parameters
<time>
The duration of the test, in seconds. The maximum time is slightly less than 429 seconds.
Example
  ! in the Declaration section
     sequential
     test time 55m
        . . .
General Information
The debug learn test time statement runs the test and returns the time the test took to run. Since the statement has some overhead time associated with it, the reported time will typically be 8 µsec longer than the actual time.
