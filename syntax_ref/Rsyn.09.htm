receive delay (VCL) (ITL)
Title: SET RECEIVE‑DELAY TIME
The receive delay statement appears in the Declaration section of the test to establish the delay time between driving a pattern of bits to the device or circuit under test (i.e., starting a vector) and receiving (examining) the response from that device or circuit.
Once established, the receive delay time remains the same for all vectors throughout the VCL test. The receive delay statement is not used in VCL tests which have timing sets (on Mux systems only).
Syntax
  receive delay <time>
     <time> is a <numeric constant>
Parameters
<time>
The receive delay time, in seconds. The range of the time is from zero to 1.59375 ms. The minimum time between two vector receives is 80 ns (50 ns in 20 MHz systems).
If not specified the delay time defaults to 400 ns.
Example
  receive delay 560n       ! 560 ns
  receive delay 0.0015     ! 1.5 ms
  receive delay 2.5u       ! 2.5 us
General Information
Timing for the vector cycle and receive delay statements is controlled in the hardware by a phase‑lock loop (PLL), whose output is a pulse named TCLK. The compiler sets the period of TCLK, based on the vector cycle and delay times requested for the test and on the constraints of the multiplier and divider circuits in the PLL. This also establishes the number of TCLKs in each vector cycle—there can be up to 255 TCLKs per vector cycle, but there will usually be less.
The compiler sets the receive delay for the test by specifying the number of TCLK periods that comes closest to generating the required delay. If the result is not sufficiently close, the compiler can include an offset, which can be between ‑30 ns and +100 ns. The compiler issues a warning if the final result is then not within 1% of the receive delay time that was requested.
In tests that have long vector cycle times and short receive delay times, the compiler sometimes sets a receive delay time that is significantly different from the time requested. The following example, which uses arbitrary values, shows how this can happen:
• received delay requested 1 µs
• period of TCLK 3.125 µs
• receive delay set 100 ns
In this case, the closest delay time, 100 ns, consists of zero TCLKs with a +100 ns offset added.
