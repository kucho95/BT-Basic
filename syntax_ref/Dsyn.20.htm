devices (ITL)
Title: BEGINNING OF A DEVICE BLOCK
The devices statement marks the beginning of a devices block. The information in this block provides the software with the descriptions of the devices in the chain, and the path names to their BSDL files.
Syntax
devices
  <device description>, <BSDL pathname>, <package name>, <compliance problem>, <disable>, <ignore(Options)>
  <device description>, <BSDL pathname>, <package name>, <compliance problem>, <disable>, <ignore(Options)>
  <device description>, <BSDL pathname>, <package name>, <compliance problem>, <disable>, <ignore(Options)>
                         . . .
end devices
Parameters
<device description>
Typically provides the name of the devices in the boundary-scan chain, such as u1, u23.
<BSDL pathname>
Provides the path that the software must use to find the BSDL file for a specific device in the boundary-scan chain.
<package name>
Provides the physical package type to use for a specific device. This allows the software to select the proper part of a BSDL file for devices that can have more than one package.
<compliance problem>
Tells the software if the specified device has some kind of problem complying with the IEEE standard. If yes is specified, the device will be considered TAP only. If no is specified, full boundary-scan test capability is employed.
<disable>
Tells the software to use boundary-scan disabling when the device must be disabled.
<ignore(Options)>
Tells the software to ignore during the boundary-scan test the following options: instruction, deviceid and bypass.
Examples
devices
   "u1", "../demo_original/custom/74bct8374", "DW_PACKAGE", no
   U2", "../demo_original/custom/74bct8374", "DW_PACKAGE", no, disable, ignore(instruction,deviceid)
                    . . .
end devices
