testplan generation (BT-Basic)
Title: GENERATE A TESTPLAN
The testplan generation statement invokes the testplan generator which writes your testplan. The testplan generator uses the testorder file. It merges a testmain into the testplan.
If you want to use a custom testmain, copy it to your ipg directory, ipg/testmain. The testplan generator will search for a testmain in your ipg directory first, if it does not find one, it will use a standard testmain from $I3070_ICT_ROOT/standard.
Syntax
  testplan generation
  testplan generation <option list 1>
  testplan generation; <option list 2>
  testplan generation <option list 1>; <option list 2>
     <option list 1> can be:   <directory name>
                               <directory name>, <error variable>
                               <error variable>
        <directory name> is a <string expression>
        <error variable> is a <numeric variable>
     <option list 2> can be:   <item>
                               <item>, <item>
                               <item>, <item>, . . . , <item>
        <item> can be:   <window>
                         <wait>
                         <experience level>
                         <backup level>
           <window> can be:   window
                              nowindow
           <wait> can be:   wait
                            nowait
                            failwait
           <experience level> can be:   standard
                                        advanced
                                        expert
           <backup level> can be:   numbered
                                    unnumbered
                                    nobackup
Parameters
 
<option list 1>
Can be either the directory pathname, or an error variable, or both.
<option list 2>
A list of optional parameters that determine how the statement works. The options are described below.
<window>
Specifies whether or not a new window is automatically opened when the statement is executed. Permissible values are:
• window – A new window is opened.
• nowindow – Suppresses the opening of a new window.
<wait>
Specifies how the command executes. Permissible values are:
• failwait – The statement executes and, if a failure occurs, the results remain on the screen so you can examine them.
• nowait – The statement executes and does not pause for you to examine the results.
• wait – The statement executes and the results remain on the screen so you can examine them.
<experience level>
Sets the length (thoroughness) of the error messages the user receives and can also be used to restrict the user to a subset of the full system features. Permissible values are: standard, advanced, and expert.
<backup level>
Determines if the system stores an unchanged copy (a backup) of files before modifying them, and how the backup is stored. Permissible values are:
• nobackup – No file backup is made.
• numbered – Makes up to nine backups, each numbered sequentially with .#~, such as file.1~. Number one is the most recent backup. When more than nine backups occur, the oldest file is discarded, and the others are renumbered.
• unnumbered – A single backup is made. The backup file name is appended with a tilde (~); for example, file~.
Example
  testplan generation "/boards/cpu_board",E
                                  ! "/boards/cpu_board" is the board directory.
                                  ! E is the error variable.
  testplan generation; unnumbered
                      ! Run the testplan generator on the current directory and
                      ! make a single backup of any files that get modified.
