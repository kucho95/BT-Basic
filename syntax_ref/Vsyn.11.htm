verify (BT-Basic)
Title: VERIFY FIXTURE WIRING
Use the verify function and the guided probe to check the wiring of your test fixture. You can check the wiring to: nodes, devices, a specified node, or a specified device.pin.
The system specifies, on the screen, the point to probe on the PC board. If autostart is on (set by softkey f7), you need to touch the specified point with the guided probe and wait for the system to verify the wiring to that point. If manual start is on (set by softkey f7), you need to press the start softkey (f1), or step on the foot switch while probing the specified point. The system checks for connections from the point you are probing to all the module interface pins. If the wiring is correct the system gives you a pass indication. If the wiring is not correct (either extra contacts, or missing contacts, or both), the system gives you a failure indication.
Pass and failure information is sent to the printer is device. The system also gives you audible feedback. The information listed on the screen and sent to the printer is device includes: expected connections, missing connections, extra connections, node names, brc’s, and the resistance of the measurement. The audible feedback is unique for a pass indication and for each type of failure indication.
The verify function defines the softkeys to help you in the verification process.
Syntax
  verify <device list>
  verify all
  verify from <device.pin>
  verify all nodes
  verify all nodes on board <board #>
  verify nodes from <node id>
     <device list> can be:   <node id>
                             <device.pin>,
                             <node id>, <device.pin>
                             <device.pin>, <node id>, . . ., <device.pin>
     <node id> is a <string expression>
     <device.pin> is a <string expression>
     <board #> is an integer from 1 to 256
Parameters
 
<node id>
A string expression which represents a node name.
Node names should not contain a period (.). If a name has a period (.) as one of its characters, the period must be preceded by a backslash (\). Otherwise, the system will treat that name as a device/pin combination. Examples:
      +6.2V describes device +6, pin 2V
but   +6\.2V describes node +6.2V
<device.pin>
A string expression which represents a device pin, such as U12.6.
<board #>
A an integer that identifies the board of a panel that uses Dual-Well Shared Wiring.
Example
  verify "U12.6"                 ! Verify a specified device pin.
  verify all                     ! Verify all device pins that were entered in the
                                 ! test development software.
  verify from "U126.4"           ! Verify all device pins starting at a specified point.
  verify all nodes               ! Verify all nodes that were entered in the
                                 ! test development software.
  verify nodes from "U126_4"     ! Verify all nodes starting at a specified point.
General Information
The verify statements require the board.o and wirelist.o files; therefore, you must msi to the correct board directory and execute the load board function before executing a verify function.
