input (BT-Basic)
Title: INPUT DATA
The input function reads in free‑field format data input from the default input device. At login the default input device is the workstation keyboard but it can be changed to another device, or to a file, by the keyboard is function.
The function can have an optional prompt. When the workstation is the default input device, the prompt appears on the workstation screen to inform you what data to input. If the prompt was not supplied, then a question mark (?) is displayed for each data input request. If any other device or file is the input, then the prompt is not displayed.
When inputting from the keyboard, you respond to the prompt (or question mark) by typing the requested data. The easiest way to respond is to input one item at a time. Simply type each number or string and follow it with a RETURN. However, you can input more than one item at a time by following the rules listed below. The input data are assigned, in the order typed, to the variables listed in the function's variable list. The data must correspond, item for item, to the types (numeric or string) of the listed variables.
The input does not necessarily have to be manual; i.e., input from the keyboard. The data can also be read from a file or a device, provided the file or device is the current default. The input function reads the data sequentially, record by record. As the data is read, the system tracks its current read position by moving a pointer through the data. Unless you close the data source, i.e., designate another default device, the next access to that data then starts at the current position of the pointer, i.e., at the beginning of the next record. The file must be closed to return the pointer to the beginning of the first record.
The rules applying to the data input are listed next. At least one data item must be input for each input function.
Rules for numerical input
1 Numbers must contain only valid characters, in the proper order.
2 The delimiter between numbers can be a comma, a space, or a RETURN (EOL or EOR). Extra spaces before or after the delimiter are ignored.
3 A null input can be made to any one numeric variable, i.e., the variable retains its current value, by omitting the number and inputting just a comma (with or without spaces).
4 When all input variables are satisfied, any remaining input, up to the next EOR, is read and discarded. The input then terminates.
5 A blank line (a null record) also terminates the input. Any remaining input variables retain their current values.
6 Input data can cross record boundaries, but an individual item cannot.
Rules for string input
1 The RETURN (EOL or EOR) is a delimiter between strings. After the input, the input variable is the same length as the string assigned to it (the dimensioned length of the string cannot be exceeded; see the next step).
2 If an input string is longer than the dimensioned length of the variable to which it is assigned, the extra characters are assigned to the next variable, if there is one.
3 When all input variables are satisfied, any remaining input, up to the next EOR, is read and discarded. The input then terminates.
4 A blank line (a null record) also terminates the input. Any remaining input variables retain their current contents.
5 Input data can cross record boundaries, but an individual item cannot.
String and numerical input
When both strings and numbers are to be input, the rules listed above apply. During the input, if a number follows a string on the same line, then the string must be the same length as the dimensioned length of the string variable to which it is assigned.
Syntax
  input <variable list>
  input <prompt>,<variable list>
     <prompt> is a <string constant>
     <variable list> can be:   <variable>
                               <variable>,<variable>
                               <variable>,<variable>, . . . <variable>
           <variable> can be numeric or string
              [Use <array id>(*) to specify a complete array]
Parameters
<prompt>
A message to inform the user what type of data to input. If the prompt is omitted, a question mark is displayed until the input has been made.
<variable list>
The identifiers of the variables to which the input data is to be assigned. Any type of variable, including substrings, can appear in the list. If a complete array is specified, each element is treated like a separate input variable.
Examples
The first three examples are sequential:
  input "Enter three values", A, B, C        ! User types  22.56,  ‑13,+0.3200
  print A,B,C                ! Prints    22.56              ‑13             .32
  input "Next three", A,B,C                  ! User types   12,,18
                                             ! Note null input for variable B
  print A,B,C                ! Prints    12                 ‑13             18
  input "Next three" , A,B,C                 ! User inputs     ,,99
  print A,B,C                ! Prints    12                 ‑13             99
The next example shows different ways to input the same data to three variables:
  dim B$[8]
  input "next", A, B$, C
  print A; B$; C
     ! 1. User types‑‑   36
     !                   test
     !                   60
     !      Prints    36 test 60
     ! 2. User types‑‑   36,test
     !                   60
     !      Prints    36 test 60
     ! 3. User types‑‑   36 test     60
                ! (spaces)     ^^^^^
                ! Prints       36 test     60
     ! 4. User types‑‑   36 test, 60
     !   A contains 36 | B$ contains the string "test, 60"
     !   a question mark appears, requesting input to variable C
General Information
Note that data entered from the keyboard is checked for errors, such as entering a string where a number is required, and can be corrected (edited) immediately, while erroneous data input from a device or file can generate an error and cause your program to abort.
For imaged formatting of the data, refer to the input using function.
