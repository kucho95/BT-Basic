tied (VCL)
Title: TIED DEVICE PINS
The tied statement is used in a digital unit to help the program generators to resolve topology conflicts. The statement identifies pins that are assumed to be tied (connected together) for that unit. If those device pins are not tied on the PC board (as input to the i3070 In-Circuit Test Software), then the program generators discard that unit from the executable version of the test. (This is the only case where the program generators will reject a unit from a test for a combinatorial device.)
Any tied statements must follow immediately after the unit statement; they apply only to the unit in which they appear. The tied statements in any one unit are independent of each other; that is, the pins in one tied statement are not tied to the pins in any other tied statement. But, in any one tied statement, all of the pins (regardless of the number of groups in that function) are assumed to be connected to each other.
Any vectors executed on a group of pins which are tied together must comply with the following rules:
• if the vector contains a counter, none of the pins assigned to the counter can be tied;
• inputs (drivers) in the group must all be set to the same state;
• outputs (receivers) in the group must all be set to the same state;
• if the tied pins contain driven and received pins, then either the driven or the received pins must be off;
• if the tied pins contain any fixed outputs (receivers which are not bidirectional), then none of that group of tied pins can be driven (i.e., set to drive and on);
• a group of power pins cannot be tied;
• a group of non‑digital pins cannot be tied.
Syntax
  tied <group id>
  tied <group id>,<group id>
  tied <group id>,<group id>, . . . . <group id>
     <group id> is a <label>
Parameters
<group id>
The identifier of a group of pins which are tied.
Example
  unit "element‑inputs tied"
     tied Data_1, Data_2
     tied Clocks               ! Clocks is not tied to Data_1 and Data_2
        . . .
  end unit
