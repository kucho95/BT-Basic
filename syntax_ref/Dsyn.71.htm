drive vector at event (VCL)
Title: SET VECTOR‑DRIVE IN TIMING SET
(Mux systems only)
The drive vector function is used in a timing set to indicate at what point in the set to strobe the vector drivers (i.e., the drive states specified in the vectors which reference that timing set).
Syntax
   drive vector at event <event#>
   drive vector at event <event#> offset <time>
      <event#> is an <integer constant>
      <time> is a <numeric constant>
Parameters
<event#>
The number of the event where the vector drive is to occur. The event# must be zero (0) or greater, up to the highest numbered event in the timing set.
<time>
The offset, in seconds, from the event on which the vector drive is to occur. The value can range from ‑30 ns to 100 ns. A value cannot be used if it would place two transitions (state changes) on the same pin closer than 50 ns, or if the transition would then occur in the next vector.
When an offset is specified for a pin, that offset applies to all activities which occur on that pin throughout the VCL test.
Examples
! in the Timing section
          . . .
     timing set T4 is 16 events
        drive vector at event 2
        receive vector at event 8 offset -10n
           . . .
           at event 13 set Enable to "11"
     end timing set
           . . .
  ! in the next timing set, T0, the vectors are executed at the same time
  ! the timing set starts
  !
     timing set T0 is 8 events
        drive vector at event 0
        receive vector at event 5
           . . .
     end timing set
           . . .
General Information
Following are the minimum times between the components of the vectors:
• drive to drive — 80 ns
• receive to receive — 80 ns
