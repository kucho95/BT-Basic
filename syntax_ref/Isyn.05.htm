image (BT-Basic)
Title: I/O FORMATTING
When referenced by an I/O function, the image function allows formatted input and output of data. If an I/O function does not reference an image function, free‑format input and output is assumed.
The six I/O statements that can reference an image function are:
• enter using
• print using
• report using
• input using
• output using
• log using
 
 
 
Because of the complexity of the image function, we recommend that you read and understand Input/Output in BT-Basic Programming before attempting complex imaged formatting.
For convenience, the word specification is shortened to spec throughout the following description.
Except in a string, upper- and lowercase characters are the same, e.g., in <space spec> either x or X can be used.
Except where noted otherwise, each <spec> allows a <repeat factor> immediately preceding it: <repeat factor><spec>. For example, when specifying an <alpha spec>, aaaaa, 5a and 4aa are equivalent, and for <number descriptor>, dd.ddd is the same as 2d.3d.
Refer to General Information for an overall list of the usage rules that apply to the image function.
Syntax
  <image id>:image <spec list>
     <image id> is a <label>
     <spec list> can be:   <spec>
                           <spec>,<spec>
                           <spec>,<spec>, . . . <spec>
           <spec> can be:   <alpha spec>
                            <bit spec>
                            <digit spec>
                            <freefield spec>
                            <inhibit EOL spec>
                            <line spec>
                            <page spec>
                            <replication spec>
                            <space spec>
                            <string spec>
  <repeat factor><spec> is allowed except where noted otherwise
     <repeat factor> is a positive, integer constant
Parameters
<image id>
A label that identifies a specific image function. An I/O function references an image function by its <image id>, which must appear at the beginning of the line.
Note that an <image id> is exactly the same as a <line id>. If a branch (goto function) is made to the <image id>, the image function is ignored but any other statements on the same line is executed.
<spec>
A specification that describes the format in which data is input or output. <spec>'s are not case sensitive; they can be uppercase, lowercase, or a combination of the two. The types are:
• <alpha spec> - Specifies how ASCII characters are handled during I/O operations
• <bit spec> - Specifies how many bits are to be transferred during I/O operations. Most useful for binary data transfers via GPIB. Cannot use a <repeat factor>.
• <digit spec> - Specifies how numeric data is handled during I/O operations.
• <freefield spec> - Allows I/O operations on either ASCII characters or numeric data without regard to type. A mixture of <alpha spec> and <digit spec>. Cannot use a <repeat factor>.
• <inhibit EOL spec> - Used to prevent the automatic EOL sequence at the end of data input or output. Cannot use a <repeat factor>.
• <line spec> - Specifies how End of Line (EOL) sequences are handled during I/O operations.
• <page spec> - Used to specify page ejects (form feeds) during data output.
• <replication spec> - Allows a group of image statements to be executed multiple times.
• <space spec> - Specifies characters to be skipped during input operations, and outputs spaces during an output operation.
• <string spec> - Specifies how text strings are handled during I/O operations.
Because of their complexity, each type of <spec> is individually described. Click on the <spec> in the list above to view the descriptions.

General Information
The following usage rules apply to the image function:
1 An image function can appear anywhere in a program, but it must always be the first function on the line. However, the statements are local to the environment in which they are located. For example, an image in one subroutine cannot be referenced from another subroutine, or from the main program.
2 Any number of input/output statements can reference the same image function.
3 An image function can contain up to 100 I/O specifications (specs), and there are three categories of specs:
• I/O field specs, which include:
– <alpha spec>
– <bit spec>
– <digit spec>
– <freefield spec>
• Control specs, which include:
– <inhibit EOL spec>
– <line spec>
– <page spec>
– <space spec>
– <string spec>
• Miscellaneous specs, which include:
– <replication spec>
An I/O field spec formats one item (or more) in the list of items to be input or output. The field spec must match the type (numeric or string, length, etc.) of the item(s) which it formats. The list of items to input or output is part of the I/O function.
Control specs format the overall input or output. They add spaces, blank lines, text (strings), etc.
The (miscellaneous) Replication spec is a group (one or more) of I/O or Control specs enclosed in parentheses to indicate that they are to be repeated as a group. The parentheses are usually preceded by a repeat factor (see next step). If not, a repeat factor of 1 (execute once only) is assumed.
4 The repeat factor is a positive, integer constant which can precede a spec to indicate the number of times that spec is to be executed. For example, x specifies one space, and either xxxxx or 5x can be used to specify five consecutive spaces, where 5 is the repeat factor.
5 Upper‑ and lowercase alphabetical characters used in specs are equivalent (does not apply to the string spec).
6 Overflow can occur if the item to be input or output is larger than its specified I/O field. Refer to the descriptions of the <alpha spec> and <digit spec> for details.
7 A maximum of 2044 characters (including spaces) can be input or output by an I/O function which references an image function, unless the image function includes one or more <line specs> (/). This is because each <line spec> allows a new record to be started, and the maximum length of a record is 2044 characters.
8 Order of Operation: An image function is ignored in a program until an I/O function which references it is encountered. When it is referenced, the image function is then executed in the following way. Each spec in the image function is selected and executed in turn. If the selected spec is an I/O field spec, it is used to format the next item from the I/O function's list of items to input or output. If the selected image spec is a control spec, then its control function is executed. After all items in the I/O function’s list have been processed, any remaining control specs in the image function are executed (any remaining I/O specs are ignored). When the input or output is finished, an EOL (End Of Line) is generated, unless the image function contains an inhibit‑EOL spec, # (GPIB or RS-232 only). The function then terminates.
9 If a spec has a repeat factor, the spec is executed the number of times specified. Then the next spec is selected.
10 If an image contains a replication spec, i.e., a group of one or more specs enclosed in parentheses, the complete sequence of specs in the group is executed the number of times specified. Then the next spec after the parentheses is selected.
11 An I/O function can have more items in its list than there are I/O field specs in the image function. In this case, the program executes the specs in the image function, and then repeats the image function from the beginning. This is repeated as often as necessary until all items in the I/O function’s list have been processed. As explained in rule 8, any remaining control specs in the image function are executed, and the EOL is generated.
12 The image function can have more I/O field specs than there are items in the I/O function’s list. As explained in rule 8, these are ignored.
