drive (VCL)
Title: SET BIDIRECTIONAL PIN TO DRIVE
The drive function is used in a vector block to specify which groups of bidirectional pins are drivers (inputs to the device being tested) for that vector. The function must precede any set to statements in the block. [This also applies to the receive function, which identifies bidirectional groups as receivers (outputs).]
The specified groups must be declared as bidirectional in the Declaration section of the test. Groups declared as inputs and outputs in the Declaration section are assigned their drive and receive directions (respectively) at that time; the directions of those groups of pins cannot be changed.
The direction (drive or receive) of a group of bidirectional pins applies only in the vector in which the direction is specified. Each vector which references that group should have an appropriate drive (or receive) function for that group; if the function is omitted, the bidirectional pins default to receivers for that vector.
A bidirectional pin has a separate driver and receiver assigned to it. Therefore, an initialize to function carries information about either the driver or the receiver, as determined in the initializing vector, but not both (see Vector T4 in the examples).
 
 
Early in the Vector Definition section of the test, define some vectors which contain drive and receive statements for the various groups of bidirectional pins; then, when applicable, use those vectors to initialize any later vectors which are to reference those groups—see the initialize to function.
Syntax
  drive <group id>
  drive <group id>,<group id>
  drive <group id>,<group id>, . . . . <group id>
     <group id> is a <label>
Parameters
 
<group id>
The identifier of a group of bidirectional pins which are to be drivers for that vector. The group must be declared as bidirectional in the Declaration section of the test.
If a bidirectional pin is not referenced at all in a vector, that pin goes to receive and to its default state when the vector is executed.
Examples
  ! the following groups are declared bidirectional in the Declaration section :
  ! Data1  Data2
     vector T1
        drive Data1 , Data2
        set Data1 to "1100"
        set Data2 to "000"
           . . .
     end vector
     vector T2
        drive Data2
        receive Data1
           . . .
     end vector
     vector T3
        drive Data1            ! defaults Data2 to "receive and X"
        set Data1 to "0011"
           . . .
     end vector
     vector T4
        initialize to T1       ! carries Data1 and Data2 as drivers
        receive Data2          ! overrides initial setting
     end vector
 
  ! Vector T4 does not work as expected:
  ! Data1 is set to "1100", as expected, because "initilize to" referenced the driver.
  ! Data2 goes to its default states because "initialize to" did not reference the
  ! receiver.
  ! To correct the vector, add the following function:
  ! set Data2 to "000"
