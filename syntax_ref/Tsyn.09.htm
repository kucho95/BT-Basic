test (BT-Basic)
Title: EXECUTE A TEST
The test statement executes the test contained in the referenced source file. The statement determines the type of test from the type of data in the file. The following test types can be executed:
• pins (CHEK‑POINT)
• shorts
• analog in‑circuit
• analog functional
• digital (in‑circuit and functional)
• mixed (analog and digital)
• VTEP (Vectorless Test EP)
When executed, test clears any existing test from memory and brings the object code (.o file) for the new test into memory. It then executes the test. If learning is on when the test is executed, test data will be learned and the test will neither pass nor fail. When the test is finished, the test remains in memory and control is returned to BT-Basic.
The appropriate board data must be in memory when the test is executed (see the load board statement).
The test statement can optionally pass parameters to the test that it executes (these are the <test parameters> in the syntax). The parameters consist of a list of numeric variables — simple variables and arrays can be included in the list. The passed parameters are assigned, in turn from left to right, to the formal parameters, in the order the formal parameters are listed in the test being executed. The correct number of variables must be passed to the test, and each passed variable must be the same type (simple variable, array variable, etc.) as the formal variable to which it is assigned.
With single (not‑mixed) tests, the analog and digital test‑type keywords are optional. You can use these keywords to document your test. However, they are ignored by the software (i.e., the wrong keyword will not cause an error).
When parameters are passed to a mixed test, again the optional digital and analog keywords, and the semicolons separating the groups of parameters, are ignored by the software. However, we strongly recommend that you use them, especially with mixed tests, to document the test for debugging purposes.
When the mixed test is executed, the test statement tries to assign the parameters, in the order they are listed, to each part of the mixed test in turn. Since it ignores the semicolons and test‑type keywords, test looks first at the digital part of the test, and second at the analog part—always in that order. If either of the two parts is not included in the mixed test, or does not require passed parameters, the test statement goes to the next part of the test.
Whether or not you use the test‑type keywords in the <test parameters>, the correct number of parameters must be passed to the mixed test. Each passed parameter must be of the same type as the formal parameter to which it is assigned.
Remember, the purpose of the test‑type keywords is to enable you to properly document your test. If you locate any of them in the wrong position in the <test parameters>, no error will occur.
 
 
Do not execute a pins, shorts, vtep, or analog in‑circuit test with any voltage source applied to the board — a battery, for example. The system will short the power out and could damage the PC board under test and the test system.
Syntax
  test <test identifier>
  test <test identifier>; <test parameters>
  test shorts
  test shorts <test identifier>
     <test identifier> can be:   <directory id>
                                 <file id>
                  <directory id> and <file id> are <string expressions>
     <test parameters> can be:
        <parameter list>
        digital <parameter list>
        analog <parameter list>
        digital <parameter list>; analog <parameter list>
        digital <parameter list>; analog <parameter list>
        digital <parameter list>
        analog <parameter list>
           <parameter list> can be:   <parameter>
                                      <parameter>,<parameter>
                                      <parameter>,<parameter>, . . . <parameter>
              <parameter> is a <numeric variable>
Parameters
 
<test identifier>
The identifier of the test to be executed. Except for mixed tests, this is always the id of the file containing the source code for the test. For a mixed test, the <directory id> of that test is required; the object code in the test.o file in that directory is then executed.
The identifier usually consists of the pathname of the file (or directory) from the board test directory (see the examples below).
<test parameters>
One or more variables passed to the test to be executed.
Example
     test "<test identifier>"
     test "pins"
     test "shorts"
     test "alt_shorts"
     test shorts                ! uses file "shorts.o" under the board directory
     test shorts "alt_shorts"
     test "analog/C128"
  ! the next two statements are equivalent:
     test "analog/R7"; Flag, Measured_value
     test "analog/R7"; analog Flag, Measured_value
     test "vtep"
     test "digital/u19"
     test "u64"; A, C(*)
     test "functional/rom_24/test"
     test "mixed/adc1"             ! directory id is used
     test "mixed/adc1"; V1, V2
  ! the next two statements are equivalent:
     test "mixed/A_to_D"; A, B(*), C, D, X1, X2, X3
     test "mixed/A_to_D"; digital A, B(*); analog C, D
