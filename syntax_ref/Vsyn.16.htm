verify faults (DEBUG)
Title: VERIFY THE TEST FAULT‑FINDING CAPABILITY
The verify faults function simulates fault conditions on one or more nodes and runs the test. Only one fault on one node is simulated for each run of the test. The results of each run (pass or fail) are sent to the printer is device. If the test fails, the fault was found; if the test passes, the fault was not found.
Five tests are run on each node. Different conditions are simulated for drivers than for receivers. Both sets of conditions are simulated on bidirectional nodes.
For an input node (driver), the function verifies the node by simulating faults and shrinking the driver threshold levels for that node. The faults established for each run are:
• Run #1: sets the node to 0 (stuck‑at 0 fault).
• Run #2: sets the node to 1 (stuck‑at 1 fault).
• Run #3: sets the node to X (stuck‑at X fault).
• Run #4: lowers the driver high (dh) threshold level on the node by 10% of the difference between that node’s dh and dl (driver low) levels.
• Run #5: raises the driver low (dl) threshold level on that node by 10% of the difference between the node’s dh and dl levels.
For an output node (receiver), the function verifies the node by removing the receiver and by expanding the receiver threshold levels for that node. The faults established for each run are:
• Run #1: removes the receiver from that node and sets the input to the receiver to 0.
• Run #2: same as Run #1, but sets the receiver input to 1.
• Run #3: same as Run #1, but allows the receiver input to float.
• Run #4: (replaces the receiver and) raises the receiver high (rh) threshold level on that node by 10% of the difference between the node’s rh and rl (receiver low) levels.
• Run #5: lowers the receiver low (rl) threshold level on that node by 10% of the difference between the node's rh and rl levels.
If any earlier debug adjustments have been made to the drivers and receivers, execute the remove adjustments function before verifying. If the adjustments are required, modify the test source file and recompile it before verifying.
The default value by which the driver and receiver threshold levels are altered is 10%. If you need a different default value, change the value of the DigitalDebug.VerifyRef: parameter in the .hp3070 file associated with your logon.
Syntax
  verify faults on <identifiers>
     <identifiers> can be:   device <designator>
                             device <designator> pins <pin‑id list>
                             groups <group-id list>
                             nodes <node-id list>
                              pins <pin-id list>
        <designator> is a <string expression>
        <pin-id list> can be:   <pin id>
                                <pin id>,<pin id>
                                <pin id>,<pin id>, . . . <pin id>
           <pin id> is a <string expression>
        <group-id list> can be:   <group id>
                                  <group id>,<group id>
                                  <group id>,<group id>, . . . <group id>
           <group id> can be:   <label>
                                <string expression>
        <node-id list> can be:   <node id>
                                 <node id>,<node id>
                                 <node id>,<node id>, . . . <node id>
           <node id> is a <string expression>
Parameters
<identifiers>
The nodes to be checked. Nodes are checked one at a time.
Example
  verify faults on groups Data_Out
