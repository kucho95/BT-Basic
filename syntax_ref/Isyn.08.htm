<digit spec>
A <digit spec> specifies the format of the field to be occupied by numeric data from the I/O function.
<number descriptor>
<number descriptor><exponent descriptor>
<sign><number descriptor>
<sign><number descriptor><exponent descriptor>
   <number descriptor> can be:  .<digit(s)>
                                <digit(s)>
                                <digit(s)>.
                                <digit(s)>.<digit(s)>
       <digit(s)> can be:
            One or more d's (or D's), representing blank‑fill characters; or
            One or more z's (or Z's), representing zero‑fill characters.
   <exponent descriptor> can be:   e – 4 spaces for exponent
                                   esz – 3 spaces for exponent
                                   eszz – 4 spaces for exponent (same as e)
                                   eszzz – 5 spaces for exponent
       <exponent descriptor> can use a <repeat factor>; for example, es3z, es2z
   <sign> can be:   s
                    m
       s and m represent 1 space for the sign of the number.
       s and m cannot use a <repeat factor>.
 
 
 
The period (.) represents the decimal point. Alternately, an r (or R) can be used in place of a period for data output when formatting in the European style. For example, formatting 3.9 with a drd format outputs 3,9.
The r does not allow the inputting of European-style numbers; it affects data output only.
The integer part of a <number descriptor> must contain either all d’s or all z's, and the fractional part must contain only d's.
INPUT using <digit spec>
When a <digit spec> is used to input data, the following usage rules apply:
1 The <digit spec> describes the format of numerical input. The same characters are used for input as are used for output, but the characters are simply used as placeholders for input:
• d – represents one numerical character
• e, eszz – same as 4d
• esz (or ESZ) – same as 3d
• eszzz (or ESZZZ) – same as 5d
• m – same as d
• r – same as d
• s – same as d
• z – same as d
• . (period) – same as d
2 The characters in a <digit spec> for input determine only the length of the field for the numerical input. So, it is not necessary that each input character is the same type as its corresponding character in the <digit spec>. For example, any of the following specs (among others) could be used to format the number ‑342.65e+12:
• Mddd.dde
• 4d.6d
• dd.8d
• zzzzzzzzzzz
3 Although the characters in the spec have no special meaning, they must still appear in the proper order (shown by the syntax) or an error occurs. Similarly, the input characters must be in the proper order and must fit properly into the field.
Example of data input with <digit spec>
    L1: image dd.dd, sd.dE, z.d
    input using L1; A, B, C

OUTPUT using <digit spec>
When a <digit spec> is used to output data, the following usage rules apply:
1 The <digit spec> is used to format numbers as they are output. The characters which can be used are:
• d – digit, blank‑fill
• e – exponent (also: esz, eszz, eszzz)
• m – minus sign or blank
• r – European style (comma in place of decimal point)
• s – sign (+ or ‑)
• z – digit, zero‑fill
• . – decimal point
2 An I/O error results if the number to be output contains any illogical characters, i.e., characters which are not allowed in a number, and characters which are allowed but which are incorrectly placed.
3 The blank‑fill character, d, is used in both the integer and fractional parts of a <digit spec> to indicate that a digit can be output to the indicated position in the field.
In the integer part of the field:
a Either a digit is output or, if that digit would be a leading‑zero, then a space is output, i.e., the number is blank‑filled.
b If the integer part of the number is too long for its field, overflow occurs and the complete field (integer and fractional part) is filled with dollar‑signs ($).
c If the number output is negative and no sign (s or m) was specified, the sign (‑) occupies the position immediately to the left of the first non‑space character (integer digit or decimal point). If there is insufficient space in the field for this sign, overflow occurs ($).
In the fractional part of the field:
a Trailing zeros are output to fill the field if it is not already full.
b If the fractional part of the number is too long for its field, it is rounded to fit the field.
c If rounding results in underflow, i.e., the number has no integer part and only zeros appear in the fractional part of the field, then a zero is output immediately to the left of the decimal point. This zero appears only if the image spec allows space for it.
4 The zero‑fill character, z, is the same as d except that z outputs leading zeros in the integer part of the field. In addition, z cannot be used in the fractional part of the field. With zero‑fill, the sign of the number (if output) is located in the first character position in the field.
5 A period (.) indicates the position of the decimal point in the field. Alternately, an r (or R) can be used for data output when European style (a period takes the place of the decimal point) is desirable. For example, formatting 3.9 with a drd format outputs 3,9.
6 An m specifies a space for the sign of the number. If the number is negative, the minus sign (‑) is output; if positive, a space is output. The sign (or space) is located immediately to the left of the first non‑space character (a digit or decimal point) in the field.
A sign space (m or s) must be included if the number is to be output in exponential form and the number is negative.
7 An s is the same as m except that, for positive numbers, the plus (+) sign is output instead of the space.
8 An e indicates the number is to be output in exponential form. Depending upon which, if any, characters follow the e, either 3, 4, or 5 spaces are left at the end of the field for the exponent. The exponent is output as the letter E followed by the sign (+ or -) and a multiplier.
The exponential formats are:
• e – 4 spaces for exponent
• esz – 3 spaces for exponent
• eszz – 4 spaces for exponent (same as e)
• eszzz – 5 spaces for exponent
Example of data output with <digit spec>
    L20: image d.dd, 12z, sd.dddde, sdd.deszzz, d.d
      print using L20; 2.33, 100, .00001, 12.56E-15, 10
        ! prints    2.33000000000100+1.0000E-05+12.6E-015$$$
        !           ‑4‑>‑12 spaces‑>‑‑‑‑11‑‑‑‑>---10---->‑‑>
        ! Notes:
        ! 1st field fits
        ! 2nd field is zero‑filled;
        ! 3rd field has a sign and exponent;
        ! 4th field is rounded to one decimal place;
        ! 5th field overflows (integer part too large).
    L30: image 2(dd.ddd), dd.dd
      output "/dev/ptr" using L30; 12.2345, ‑1.456, 1.4
        !
        ! prints    12.235‑1.456 1.40
        !            ‑‑6‑‑>‑‑6‑‑>‑‑5‑>
        ! Notes:
        ! 1st field--fractional part of number rounded up;
        ! 2nd field--minus sign fills one digit‑space;
        ! 3rd field--integer part blank‑filled, trailing zero
        !            output to fractional part.

        ! print function contains image specs;
        ! 1st field‑‑blank‑filled and rounded up;
        ! 2nd field‑‑rounded down; zero precedes decimal
