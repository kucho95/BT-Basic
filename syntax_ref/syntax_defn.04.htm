Language Conventions
Following are some conventions which apply to all statements, regardless of mode.
• Abbreviated Keywords
• Quotation Marks
• Use of Spaces
Abbreviated Keywords
It is not necessary to type all of the characters in the keywords. However, you must supply enough characters that the system can uniquely interpret the keyword. For example, cal is sufficient to distinguish between call and cat, but ca is not. The actual abbreviations are not shown in this documentation since they are dynamic and may change each time there are changes to the software. There is no lookup table of abbreviated keywords in the system; instead, the software is programmed to accept as many characters as it needs to recognize a unique keyword. The software then supplies the remaining characters, for readability. Also, when you type a statement, if you do not supply enough characters, the system indicates the error when you press the return or execute (provided that the appropriate syntax checking is on).
Quotation Marks
Except in text mode, any string constants must be enclosed in quotation marks. The syntax description of strings shows that a double quotation mark (“) is required—as in "This string is a string constant"—but either the double or the single mark (') can be typed: you may use whichever you prefer. Typing the single mark saves you from having to press the Shift key every time you need a double quotation mark; however, you must follow the conventions properly, as described below. When the system processes your typed statement it will change all the (appropriate) single quotation marks to double marks.
For each string, the opening and closing quotation marks must be the same, as shown in the following examples (the definition of Comment explains the use of the exclamation marks):
  print "Digital" ! prints Digital
  print 'Digital' ! prints Digital
  print "Digital' ! error
However, this statement is acceptable because the marks for each string are the same:
  print "Digital"; ' Test'
In the body of a string, two consecutive, double quotation marks indicate that one double quotation mark is to be inserted as a character into that string. Again, provided that all the same marks are used, either the double or the single quotation marks will produce the same result. Example 5 illustrates this.
Example 5  
  A$ = "He said ""Hello"" to his friend."
  print A$                ! prints He said "Hello" to his friend.
  B$ = 'He said ''Hello'' to his friend.'
  print B$                ! prints He said "Hello" to his friend.
  C$ = 'He said '"Hello"' to his friend.'      ! error
 
While the single quotation mark can be used in place of the double mark, the converse is not true. A single mark can be typed in a string just like any other character, but then double marks must be used to open and close that string. See Example 6.
Example 6  
  D$ = "He said 'Hello' to his friend."
  print D$                ! prints He said 'Hello' to his friend.
  E$ = 'He said 'Hello' to his friend.'    ! error
 
As stated above, whether you type single instead of double quotation marks is entirely a matter of choice, provided that you follow the conventions correctly.
Use of Spaces
The system languages use a free format that, in most cases, enables using extra spaces between the various elements in a statement without changing the statement's meaning. This enhances the readability of your program. There are a few statements where spaces either cannot be inserted, or must be inserted; these are indicated in the appropriate places in this book.
Sometimes you may want to include or exclude a space but are not sure if the syntax allows it. In this case it is a good idea to simply experiment and see what happens. If it is not allowed, then the system will return an error message so that you can correct the error before proceeding. Whether you are trying to execute the statement or use it in a program, the system will not allow you to proceed until the statement has been either corrected or deleted.
