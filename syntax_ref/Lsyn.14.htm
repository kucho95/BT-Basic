list tests (BT-Basic)
Title: LIST TESTS ASSOCIATED WITH THE BASE BOARD OR SPECIFIC VERSIONS
When using Multiple Board Versions, use the list tests statement to list tests associated with the base board or specific versions. The version label parameter allows you to specify the version of the board.
Syntax
  list tests
  list tests; version <version label>
  list tests <to/over> <file name>
  list tests <to/over> <file name>, <backup level>
  list tests <to/over> <file name>; version <version label>
  list tests <to/over> <file name>; version <version label>, <backup level>
     <version label> is a <string expression>
     <to/over> can be: to
                       over
     <file name> is a <string expression>
     <backup level> can be: numbered
                            unnumbered
                            nobackup
Parameters
<backup level>
The type of backup when listing to a file that already exists.
• nobackup – No file backup is made.
• numbered – Makes up to nine backups, numbered sequentially with .#~ (for example, file.1~). Number one is the most recent backup. When more than nine backups occur, the oldest file is discarded, and the others are renumbered.
• unnumbered – A single backup is made, indicated with a tilde (~) in the file name.
Examples
• List all base-board tests to the screen
      list tests
• List all base-board tests to file called "base_board"
      list tests to "base_board"
• List version 1 tests to the screen
      list tests; version "version_1"
• List version 2 tests to a file and instructs the compiler to save a backup file before making any changes
      list tests to "version_2"; version "version_2", unnumbered
 
General Information
Tests that are unique to the specified version include the version label. In the followinig example, the test for U2 is unique to version 1:
  test "digital/u2" version "version_1"
Because the tests that are unique to a version include the version label, you can use the list tests statement to find the tests that are unique for a version. For example:
  list tests to "version_1"; version "version_1"
  get "version_1"
  findn "version"
