Representation of Numbers
This section discusses the range of numbers and the accuracy of calculations, and the number formats: standard format and scientific notation. Also described is the twos‑complement representation of binary numbers (used by the string functions), and the automatic rounding to integers of non‑integer values (reals) supplied by the user when an integer value is required.

Range of Numbers and Calculations
The range of decimal numbers which can be stored in the system depends upon the controller. Generally, both the positive and negative range is greater than from 10–300 to 10+300, and approximately 16‑digit accuracy is maintained in calculations.
This range and accuracy should be more than adequate for board testing purposes. However, it could be of concern in networked systems, because the range of different controllers often differ from each other. When dealing with extremely small and large numbers, it may be possible to generate numbers on one controller that cannot be accepted by another controller because they are beyond its range.
Displaying Numbers
Numbers are output, printed or displayed on the workstation screen, with up to twelve significant digits; the least significant output digit is rounded, if appropriate, depending on the value of the remaining (internal) digits.
If a number is input with too many digits, the value is rounded accordingly; however, the extra digits are counted so that the decimal point is properly located.
Standard Format
Numbers are output in standard format with up to twelve significant digits. In general, numbers look as you would expect them to look in the absence of any special instructions: 10 looks like 10, and not +000010.000, for example. The following rules apply:
• A leading space is allowed for the sign. If the number is negative, the minus sign (‑) is output in that space; if the number is positive, the space is left blank.
    ‑35.68
    1.246
• If the number is an integer, the decimal point is not output.
    154
    ‑399006
• If the number is a fraction, leading zeros before the decimal point are suppressed.
    ‑.00642
    .0000000038
    .489
• Nonsignificant zeros after the decimal point are truncated.
    print 1.689000000  ! prints  1.689
• If the absolute value of a number is too large (>= 1E+12) or too small (<= 1E‑12) to be represented in standard format, the number is output in Scientific Notation.
Scientific Notation
Numbers are output in Scientific Notation if they are too large (>= 1E+12) or too small (<= 1E‑12) to be represented in standard format. Scientific Notation has up to twelve significant digits and a four‑character exponent.
• The decimal point is placed immediately after the most significant digit.
• All leading zeros, and all nonsignificant zeros are suppressed.
• The exponent consists of the letter E followed by the sign of the exponent and either one or two significant digits.
    3.689E+15
    ‑5.2E‑12
    3E+22
 
    print 56.2e+15  ! prints  5.62E+16
Twos‑Complement Representation of Numbers
Many functions are used by the test developer to convert between the four numbering systems (decimal, binary, octal and hexadecimal) and to return values resulting from performing logical operations.
These functions assume decimal integer values, and either 16‑bit or 32‑bit, twos‑complement representation of the values. The 16‑bit or 32‑bit operation is selectable by the option bit statement.
When twos‑complement representation is used:
• a positive decimal number is represented by its binary equivalent;
• a negative decimal number is represented by the twos‑complement of the binary equivalent of the absolute value of that decimal number.
Depending on the number of bits selected, decimal numbers in the following range can be represented as:
• –(2^15) <= decimal value <= (2^15)–1
(2^15 = 32768)
or,
• –(2^31) <= decimal value <= (2^31)–1
(2^31 = 2147483648)
The most significant of the sixteen (thirty-two) bits is referred to as the sign‑bit because it represents the sign of the (decimal) value; a 1 indicates a negative value, and a zero a positive value. Therefore, if a twos‑complement number has a sign‑bit equal to one, it represents a negative, decimal value. To determine that value, the number must first be converted to binary, and then the minus sign must be added to the (positive) decimal equivalent of that binary number. For example (using sixteen bits):
  1111111111100110 -- 2's complement
                ‑1
  ‑‑‑‑‑‑‑‑‑‑‑‑‑‑‑‑
  1111111111100101 -  1's complement
  0000000000011010(binary) = 26(decimal)
the 2’s complement number represents ‑26 (decimal).
If the sign‑bit is a zero, then the number is the binary equivalent of a positive, decimal value. With 16‑bit operation, if the number has less than sixteen bits, then leading zeros are assumed; so any number with less than sixteen bits is positive. Similarly, with 32‑bit operation, numbers with less than thirty-two bits are positive. See the examples in Table 2.

Automatic Rounding of Reals to Integers
Several statements and functions (the binand function, for example) have parameters which must be integers, as specified in the syntax. If you supply non‑integer values (that is, reals) for these parameters, rather than generating an error, the system automatically rounds the reals to their nearest integer value. The rounding algorithm used is as follows:
• For positive numbers, if the fractional part of a number is 0.5 or greater, the number is rounded up to the next higher integer value; if the fractional part is less than 0.5, it is truncated.
• For negative numbers, the absolute value of the number is rounded, as for positive numbers, and then the minus sign is added.
If the supplied value is negative but the value requires a positive parameter, an error results.
The purpose of the automatic rounding is to enable the to use of variables for the integer parameters and allow the program to calculate the values. If a non‑integer value is supplied, the program rounds the value and continues, instead of generating an error.
