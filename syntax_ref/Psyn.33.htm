preset counter (VCL)
Title: PRESET COUNTER & EXECUTE THE VECTOR
The preset counter function is used in a digital unit to execute a vector which contains a counter; first, it presets the counter to its initial value, and then it executes the vector.
A vector with a counter must be executed first by preset counter, to initialize the counter, and subsequently by count statements, to increment the counter (the vector cannot be executed by the execute function). Each time a vector with a counter is executed, its non‑counter pins behave just as they would in any other vector; that is, they are set to the states specified in the vector.
Once a counter has been started, other vectors can set its pins to different states without interrupting the count sequence. The next time a count is executed, the counter will set to the next count in its sequence, as if it had not been interrupted. The counter vector can be preset again (preset counter function) to restart at the counter's initial value.
In addition to identifying the vector to be executed, the function can optionally include some combination of secondary keywords, as shown in the syntax format below. Refer also to the separate descriptions of the compress, exit if pass, piped and sync statements for more information.
 
Table P-4 Secondary keywords 
Keyword
Description
arm
Arm the time interval counter (i.e., frequency, pulse width, and time interval) on the ASRU card to start timing. The setup must first be made in the analog portion of a mixed test.
capture
Add the states of the capture pins to the capture RAM.
compress
Add the received response (from all pins that are not off) to the CRC; cannot be used in a controller loop, homing loop or unit disable test.
drive
Drives pin states from the specified variable.
drive data
Drives the current set of pin states from the specified data block.
exit if pass
Exit a homing loop when the device is in the required state (i.e., the received outputs match the expected response in the current vector).
piped
Specifies the piped vectors in homing loops (see Advanced Testing With VCL in Digital Testing)
receive
Receives the pin states defined in the specified variable.
receive data
Receives the pin states defined by the current setting in the specified data block.
sync
Generate the sync pulse which appears at a BNC connector on the side of the testhead.
trigger acv
Trigger the AC voltmeter on the ASRU card. The setup must first be made in the analog portion of a mixed test.
trigger arb
Trigger the ARBitrary waveform generator. This function is the same as trigger source but can be used more than once between continue analog statements (see General Information).
trigger dcv
Trigger the DC voltmeter on the ASRU card. The setup must first be made in the analog portion of a mixed test.
trigger detector
Same as trigger dcv.
trigger digitizer
Trigger the digitizer. This function is the same as trigger acv but can be used more than once between continue analog statements—but, see General Information, below.
trigger external
Trigger the external port set up in the analog portion of a mixed test.
trigger source
Trigger the source (i.e., sine, triangle, and square wave) on the ASRU card. The setup must first be made in the analog portion of a mixed test.
wait
Causes the test to wait for a trigger on the wait lines before resuming.
Because of the purpose of each option, only certain combinations can be used. Allowable combinations of options are:
• Use these options alone or with any other options:
• drive
• drive data
• receive
• receive data
• sync
• wait
• Use these options alone or with options A:
• exit if pass
• piped
• Use these options alone, or with options A, or with any combination allowed in D:
• capture
• compress
• These options can be used only in mixed tests; they can also be used with options A and C. Each one can be used only once after each return from the analog test to the digital test. They can be used alone or in any combination of the following:
• arm
• trigger acv or trigger arb or trigger dcv or trigger detector
• trigger external
• trigger source or trigger digitizer (cannot be used with trigger acv or trigger arb)
Syntax
  preset counter <vector id>
  preset counter <vector id> <options>
     <vector id> is a <label>
     <options> can be any one, or any allowable combination, of:
        arm
        capture
        compress
        drive <variable>
        drive data <data block id>
        exit if pass
        piped
        receive <variable>
        receive data <data block id>
        sync
        trigger acv
        trigger arb
        trigger dcv
        trigger detector
        trigger digitizer
        trigger external
        trigger source
        wait
           <variable> can be:   <numeric variable id>
                                <numeric array id> (<element>)
           <...id> is a <label>
           <element> is a <integer constant>
Parameters
 
<vector id>
The identifier of the vector to be executed; the vector must contain a counter. The vector cannot be a formal vector in a digital subroutine; it must have been defined in the Vector Definition section of the test.
If the compress secondary keyword is used, all outputs to be compressed must be on (i.e., set to 1 or 0 when the vector is executed); outputs not to be compressed, must be set to X (off). The pins in the counter will not be compressed.
<variable>
The simple variable or array element that contains the pattern of bits to be friven to, or received from, a group of pins.
<data block id>
The data block that contains the pattern of bits to be driven to, or received from, a group of pins.
<label>
This is the same as a BT-Basic <label>. It can contain up to 32 characters, but with no spaces. The first character must be an uppercase letter and the remaining characters can be letters, numbers, or underscores (_).
Example
  ! in the Vector Definition section
        . . .
  vector Count1
     set Enable to "11"
     set Inputs to "00101"   ! will preset counter to 5
     set Mode to "00"
     upcounter Inputs        ! establishes an upcounter on the pin‑group named "Inputs"
  end vector
        . . .
  ! in the Vector Execution section
        . . .
     preset counter Count1     ! 11 00101 00  ‑‑ resulting vector
     count Count1              ! 11 00110 00
     count Count1              ! 11 00111 00
        . . .
  ! random examples of "preset counter" statements
     preset counter Outputs compress
     preset counter Data0 sync compress
     preset counter Outputs compress
     preset counter Outputs sync compress
     preset counter Outputs trigger source trigger dcv wait arm
     preset counter V20 drive A(22)
     preset counter V21 receive A(6)
     preset counter V22 drive A(14) receive X(14) drive B(14) ! must use the same indices
     preset counter V23 drive data Hex_record_Addresses
General Information
Multiple trigger arb and trigger digitizer options can be specified without executing a continue analog function between them. However, make certain that there is at least one active vector executed between the trigger options, to reset the trigger drivers on the ASRU card—a trigger cannot be initiated if its driver has not been reset. Consider the following example:
  execute V1 trigger arb
  wait 20m
  execute V1 trigger arb
A wait consists of some number of no‑op vectors that execute keeps on all drivers, including the trigger drivers on the ASRU card. Therefore, since the trigger drivers have not been reset, the second trigger will not occur. To avoid the problem, place at least one vector that is not a no‑op vector either before or after the wait. If you do not, the compiler will issue a warning.
