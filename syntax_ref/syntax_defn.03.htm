Interpreting Syntax
All of the statement descriptions in this documentation use the same syntax conventions and definitions. This chapter describes those conventions and definitions.
Each statement is described in the Syntax Reference using a standard, five‑part format:
• A description of the statement, its use and its operation.
• A formal presentation of the syntax, showing the formats the statement can have.
• A reference description of each statement’s parameters, together with limits and any other details.
• Examples of the statement, showing how to use it.
• A general information section with any additional information which might help you to use the statement more effectively.
Syntax Examples
The statement used to rename a file (rename) has only two possible formats, so both of them are shown:
Example 1  
rename "<old name>" to "<new name>"
rename "<old name>" to "<new name>", <error variable>
 
This syntax indicates that the keywords (rename and to) and two names must always be typed, but the error variable (with the comma) is optional because it does not appear in both formats. The angle brackets (< >) indicate that you supply the information described within the brackets. For example, if you have a file whose old name is infile and you want its new name to be outfile, you could type:
  rename "infile" to "outfile"
or, to include an error variable:
  rename "infile" to "outfile", Fault
Here, Fault is the name given to the error variable. See Definitions.
Where a statement has many possible formats, parts of the syntax are compressed and then expanded later. This enables you to see the overall structure of the format first and then examine the details as you need them. As an example, look at the syntax for the outputs limited to statement, shown next. This statement indicates how many outputs of a digital device are all high (1), or low (0), at the same time—this information is part of the data used by the system to determine how long a device can be stressed safely.
Example 2  
  outputs limited to <maximum> at "<state>"
  outputs limited to <maximum> at "<state>", <maximum> at "<state>"
 
<maximum> is a <numeric constant>, <state> can be 1 or 0.
Following are some example statements:
  outputs limited to 8 at "0"
  outputs limited to 6 at "0", 12 at "1"
  outputs limited to 15 at "1", 2 at "0"
In the syntax for the outputs limited to statement, the first level tells you that the statement can have two forms: with either one <maximum>/<state> combination, or two <maximum>/<state> combinations. The second level explains what you need to supply for the <maximum> and <state> parameters. For <maximum>, you supply a number (numeric constant), such as 1, 15, 9, representing the number of outputs that might all be at one state at the same time.
For <state>, you again have two choices.
The syntax for the shift function requires two values: the value to be shifted and the amount to shift it. This statement is shown in two steps:
  shift (<value>, <shift>)
<value> and <shift> are <numeric expressions>
This tells you immediately which element represents the value and which the amount to shift. Here, both parameters are numeric expressions, so you can use anything allowed in a numeric expression (a constant, a variable, etc.), such as:
  shift (13, 3)
  shift (A * 6/B, Sum)
Notice that you can tell the expressions apart because they are separated by a comma, which is also shown in the syntax.
Now let's look at a statement which is very much more complex: the cat statement. cat lists (catalogues) the file‑names contained in a directory. This syntax has to be broken into several levels.
Example 3  
  cat
  cat <parameters>
  cat <parameters>; <option>
  cat; <option>
<parameters> can be:
<instructions>
<instructions>, <error variable>
<instructions> can be:
    <directory id>
<directory id> to <file id>
<directory id> and <file id> are <string expressions>
<error variable> is a <numeric variable>
<option> can be:
    short
    protect
 
The example syntax shows that the cat statement can have any of four general formats:
• cat by itself,
• cat followed by some parameters,
• cat with parameters and an option, or
• cat with just the option.
Notice the use of punctuation to set off certain parts of the syntax. As a general rule, a comma is used to separate the elements in the syntax, although in this case a semicolon is used before the <option>.
At the first level of this syntax, there are two groups of elements shown as <parameters> and <option>. These represent elements which also can have more than one format. Compressing these elements into groups, rather than showing all possible combinations at the first syntax level, emphasizes the structure of the cat statement. Once that is understood, the formats that these elements can have is shown.
The optional <parameters> element can have many formats so it has to be broken into the elements shown in various combinations of <instructions> and <error variable>. Of these, the <error variable> is simply a <numeric variable> so it requires only one more line, lower down in the syntax. (The <error variable> is defined later in this chapter.)
On the other hand, the <instructions> element is more complex than the <error variable> so must be broken into more elements. As shown, <instructions> can have one or two <id>’s, one for a directory and one for a file (id is the abbreviation for identifier, which is a name enclosed in quotation marks). There is also a secondary keyword (to), which must be included if the <file id> is used. The next level of syntax indicates that the two <id>’s must be <string expressions>.
Here are some example cat statements:
  cat "tests" to "printer"
which lists the contents of a directory called test into a file called printer, and
  cat to "printer", Fault
which lists your current directory into file printer and specifies an error variable, Fault.
In the syntax, the <option> is similarly broken into its component parts; in this case, if you want to use an option then you have a choice from just two, short or protect; for example:
  cat "tests"; short
Special Terms
There are several terms, such as numeric expression and identifier (or id), which appear in many syntaxes; these terms are defined separately (see Definitions). All of the syntax descriptions are eventually reduced to these terms so that the syntaxes can be interpreted precisely. For clarity, the number of these specially defined terms has been kept to a minimum.
Syntax Conventions
Table 1 contains a summary of the syntax conventions used in this documentation; the examples that you have already seen in this chapter use these conventions.
 
Table 1 Syntax conventions 
Convention
Description
<element>
The contents of the angle brackets (<>) describe the type and purpose of the element which you supply. The element itself may have to conform to some specific syntax format.
element
Elements which are not enclosed in angle brackets must be typed exactly as shown. This applies to the keyword (or action part) of each statement. It also applies to punctuation, such as a comma used to separate parameters, and the parentheses used to group them.
. . .
Ellipsis indicates that you can repeat a set of elements (including any punctuation) zero or more times. A repeatable set is easily identified because it appears twice on the same line as, and preceding, the ellipsis.
<element 1>
<element 2>
<element 3>
Elements which are stacked one above the other represent the different formats for a statement or for an element.
The syntax also shows you which elements are optional. If an element appears in all forms of the syntax for a statement, then that element is not optional and you must supply it when you type that statement.
Example 4  
  binand (<numeric expression>, <numeric expression>)
 
The binand function (binary AND) has no options; the keyword (binand), the parentheses and the comma must all be included as shown because they are not enclosed in angle brackets. The two numeric expressions must also be there, but, since they are in angle brackets, you decide on their contents. For example:
  binand (15, 6)
  binand ((8*A+6)/3,5)
