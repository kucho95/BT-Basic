call (BT-Basic)
Title: CALL SUBROUTINE
The call function is used to invoke a subroutine. When the call is made, control is transferred to the selected subroutine. When the exit is made from the subroutine, control returns to the function immediately following the call function which invoked that subroutine.
Subroutines can be executed only by means of calls; for instance, it is not possible to use a goto to branch into the subroutine and start executing the statements there. (Other statements which can call a subroutine are on, on break and on error.)
When the subroutine is called, a list of parameters (data) can be optionally passed to it. Each passed parameter is assigned, in turn, to a parameter from the subroutine's formal parameter list, in the order in which the parameters appear in the lists. Each passed parameter must match the formal parameter to which it is to be assigned (i.e., numeric or string, strings of the proper length, etc.).
As well as operating on passed parameters, the subroutine can also operate on local variables, and on global variables (see the global function).
Syntax
  call <sub id>
  call <sub id> (<parameter>)
  call <sub id> (<parameter>,<parameter>)
  call <sub id> (<parameter>,<parameter>, . . . <parameter>)
     <sub id> is a <label>
     <parameter> can be:   <numeric expression>
                           <string expression>
                           <array id>(*)
                           @<name>
         <name> is a <label>
Parameters
 
<sub id>
The identifier of the subroutine to be invoked. The subroutine must exist before a call function can be executed. (Refer to the sub function and to the definition of <label>).
<parameter>
An actual parameter to be passed to the subroutine. A parameter can be either a source of data on which the subroutine is to operate, or a destination where the subroutine is to send results. A parameter can be both at the same time. Each passed parameter must be of the same type as the formal parameter which is assigned to it. The number of parameters passed must be the same as the number of formal parameters. Up to 31 parameters can be passed to a subroutine.
 
A parameter can be numeric or string; it can be a value, a variable id, or an @<name>. A variable can be a simple variable, an array element, an array, or a substring. An @<name> represents a file or device. A substring can not be a destination.
The subroutine can change the contents of any variable, file or device passed to it as a parameter; the changes remain in effect after the exit from the subroutine. However, if the parameter is a substring, then that substring retains its original contents after the exit, regardless of any changes the subroutine may have made.
Examples
  ! MAIN:
     dim A(3,6,25), B(25), C(4,8,30,10), D(30,10)
     Message$ = "Test #1:" \ assign @Book to "/dev/prtr"
        . . .
     call Average (Message$,A(*),B(*),Hi,Lo,@Book)           ! CALL SUB
        . . .
     call Average ("Test#2:",C(*),D(*),2*pi*Freq,Xc,@Book)   ! CALL SUB
        . . .
  end                                 ! **END OF MAIN** SUBROUTINE:
        sub Average (Type$, Value(*), Results(*), High, Low, @Printer)
           . . .
        subend
  ! Main2
     A = 20 | T$ = "Tom"
        call Print_Name               ! prints Tom is 20 years old.
           . . .
  end
     ! Subroutine2
        sub Print_Name
           global A, T$
           print T$; " is "; A; " years old."
        subend
