file (VCL)
Title: ASSIGN VALUES FROM A FILE TO A DATA BLOCK
The file function appears in a data block in the Vector Definition section of a test to assign values to the block. The values are saved in a file and read into the block at runtime. Two types of data can be read: numerical values and formatted data.
Numerical values are integer constants and are read sequentially from the file specified in the function. The values are saved in 32-bit, two’s complement format and can represent values or ASCII characters. The values are binary and are not subject to format statements.
Formatted data consists of pin states formatted either as Intel Hex Format, or as Motorola S-Records. These records are automatically split into their address part and data part when they are read into the block. The function's <data type> parameter determines which part is saved in the block.
The values are read from the block in the same order they are assigned to the block. Also see the values function.
Syntax
  file <file id> <number of values>
  file <file id> <number of values> <record format> <data type>
  file <file id> <number of values> <record format> <data type> <data modifier>
  file <file id> <number of values> <record format> <data type> <step>
     <file id> is a <string constant>
     <number of values> and <step> are <integer constants>
        <record format> can be:   hex record
                                  s record
        <data type> can be:   address
                              data
        <data modifier> can be: reuse
                                unused
                                user <integer address>
Parameters
 
<file id>
The pathname of the file that contains the data that is to be read into the block. The reference directory relative to which the pathname is interpreted is the digital test directory, not the board directory.
<number of values>
Specifies the number of records that are read from the file. Each record must contain a single value. Reading starts with the first record in the file. The file should contain at least the number of values specified. If there are more, the extra values are ignored. If there are fewer, 1 states are driven for the missing values.
<record format>
The format of the records in the file to be read.
<data type>
For formatted records, specifies the part of each record the address part or the data part that is to be assigned to the data block.
<data modifier>
Specifies the method for handling the end of data condition. See File Statement Options in Flash Programming.
<step>
The value by which the address that is driven to the device pins is incremented each time the data is incremented. This is not normally used. It is required only for writing or reading multi-byte data into devices in parallel when the devices are addressed individually.
Examples
  ! in the Declaration section of the test
     . . .
  assign Write_enable to pins 10,12
  assign Data_bus to pins 1, 2, 3
     . . .
  ! in the Vector Definition section of the test
     . . .
  data FlashRAM_Data to groups Data_bus
     values 2, 3, 7, 6
     values A(3), A(9), A(21)
     values B(2:51)
     file "Data_File" 120
  end data
  ! in the Vector Execution section
     . . .
  execute V1 drive data FlashRAM_Data
     . . .
  ! The next two blocks read 180 S-records; the first block saves addresses
  ! and the second block saves the data. Addresses are driven to pin-group
  ! "Address1" and data is driven to pin-group Data1
  data S_Record_Address to groups Address1
     file "S_records" 180 s record address
  end data
  data S_Record_Data to groups Data1
     file "S_records" 180 s record data
  end data
  ! in the Vector Execution section
  . . .
  execute Data_Write drive data S_Record_Address
