probe selection (BT-Basic)
Title: RUN PROBE SELECT
The probe selection function determines the best probe type and location for each node.
You can use this function in the incremental mode to incorporate changes to the board under test. To run probe selection on a specified fixture directory, use the probe selection on function.
Syntax
  probe selection
  probe selection <option list 1>
  probe selection; <option list 2>
  probe selection <option list 1>; <option list 2>
     <option list 1> can be:   <directory name>
                               <directory name>, <error variable>
                               <error variable>
        <directory name> is a <string expression>
        <error variable> is a <numeric variable>
     <option list 2> can be:   <item>
                               <item>, <item>
                               <item>, <item>, . . . , <item>
        <item> can be:   <window>
                         <wait>
                         <experience level>
                         <backup level>
           <window> can be:   window
                              nowindow
           <wait> can be:   wait
                            nowait
                            failwait
           <experience level> can be:   standard
                                        advanced
                                        expert
           <backup level> can be:   numbered
                                    unnumbered
                                    nobackup
Parameters
 
<option list 1>
Can be either the directory pathname, or an error variable, or both.
<option list 2>
A list of optional parameters that determine how the function works. The options are described below.
<window>
Specifies whether or not a new window is automatically opened when the function is executed. Permissible values are:
• window – A new window is opened.
• nowindow – Suppresses the opening of a new window.
<wait>
Specifies how the command executes. Permissible values are:
• failwait – The function executes and, if a failure occurs, the results remain on the screen so you can examine them.
• nowait – The function executes and does not pause for you to examine the results.
• wait – The function executes and the results remain on the screen so you can examine them.
<experience level>
Sets the length (thoroughness) of the error messages the user receives and can also be used to restrict the user to a subset of the full system features. Permissible values are: standard, advanced, and expert.
<backup level>
Determines if the compiler stores an unchanged copy (a backup) of files before modifying them, and how the backup is stored. Permissible values are:
• nobackup – No file backup is made.
• numbered – Makes up to nine backups, each numbered sequentially with .#~, such as file.1~. Number one is the most recent backup. When more than nine backups occur, the oldest file is discarded, and the others are renumbered.
• unnumbered – A single backup is made. The backup file name is appended with a tilde (~); for example, file~.
Example
  probe selection "/boards/cpu_board",E
                                  ! "/boards/cpu_board" is the board directory.
                                  ! E is the error variable.
  probe selection; unnumbered     ! Run Probe Select on the current directory and make
                                  ! a single backup of any files that gets modified.
General Information
The probe selection function is run automatically during the test development process.
