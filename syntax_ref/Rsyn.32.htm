re‑save (BT-Basic)
Title: SAVE THE CONTENTS OF THE WORKSPACE IN AN EXISTING FILE
The re‑save statement stores the lines currently in the workspace into an existing file. The workspace remains unchanged. The file must exist when this statement is executed; except for this requirement, re‑save is the same as the save statement.
If the mode is not specified, the current mode of the workspace is recorded in the file. If the mode is specified, it must be the same as the current mode of the workspace, or be text. If text is specified, that mode is recorded in the file, regardless of the current mode of the workspace. After the re‑save, the file has the mode just recorded, regardless of its original mode or contents.
Note that a user’s experience level can affect re-save on certain types of files. For example, you need the expert experience level to re-save a file whose mode is wirelist.
Note to the System Administrator: The experience level is set in each user’s .hp3070 environment file.
Syntax
  re‑save
  re‑save <file id>
  re‑save <file id>,<parameters>
  re‑save,<parameters>
  re‑save <mode>
  re‑save <mode> <file id>
  re‑save <mode> <file id>,<parameters>
  re‑save <mode>,<parameters>
     <file id> is a <string expression>
     <mode> can be:
        analog
        basic
        configuration
        digital
        pins
        safeguard
        shorts
        states
        testorder
        text
        wirelist
     <parameters> can be:
        <first line>
        <first line>,<last line>
        <first line>,<last line>,<error variable>
        <first line>,,<error variable>
        ,<last line>
        ,<last line>, <error variable>
        ,,<error variable>
           <first line> is a <numeric constant>
           <last line> is a <numeric constant>
           <error variable> is a <numeric variable>
 
 
 
If an intermediate parameter is omitted, the syntax requires a comma if a later parameter is included.
Parameters
<file id>
The identifier of the file where the lines are to be saved. This file must exist, and it cannot represent a device.
If the id is omitted it defaults to the file that was previously read by a get or load, provided that file is still open.
<mode>
The mode to be recorded in the file.
<first line>
A positive integer which specifies the number of the first line to be saved in the file. The line must exist in the workspace.
If this parameter is omitted, it defaults to the first line in the workspace.
<last line>
A positive integer which specifies the number of the last line to be saved in the file. Any subsequent lines in the workspace are ignored.
If this parameter is omitted, it defaults to the last line in the workspace.
If <last line> is specified and it is beyond the last line in the workspace, the existing last line is assumed.
<last line> must be equal to, or greater than, the number of the first line to be saved.
<error variable>
The identifier of an error variable.
Example
  "/market/ts/my‑file"             ! Brings the file into the workspace
  .....
  re‑save       ! Saves the workspace in the file; replaces current contents of the file
  msi "/production/test/a3564b"
  re‑save "report1", 25            ! Saves lines 25 to end of workspace
  re‑save "report2", 62,136        ! Saves lines 62 through 136
  re‑save "report3",,, Alpha       ! Saves complete workspace; error variable specified
                                   ! - note the "place‑saving" commas
  re‑save text "newfle",5,18,Err
General Information
If the system is switched off, or goes down, during the re‑save operation, both the contents of the workspace and the original contents of the file will be lost. Thus, it is good practice to backup your files periodically.
The re‑save and re‑store statements are identical.
