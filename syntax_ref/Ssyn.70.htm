sub (BT-Basic)
Title: SUBROUTINE DECLARATION
The sub statement declares the name of the subroutine and lists its formal parameters, if any. sub must be the first statement in the subroutine. The formal parameters represent variables, files or devices; data will be passed (assigned) to the parameters by the call statement when the subroutine is called. During execution of the subroutine, any time a formal parameter is referenced, the subroutine accesses the passed parameter assigned to that formal parameter.
As well as operating on passed parameters, the subroutine can operate on local variables, and on global variables (see the global statement).
Syntax
  sub <sub id>
  sub <sub id> (<parameter>)
  sub <sub id> (<parameter>,<parameter>)
  sub <sub id> (<parameter>,<parameter>, . . . <parameter>)
     <sub id> is a <label>
     <parameter> can be:   <simple variable id>
                           <array id>(*)
                           @<name>
        <name> is a <label>
Parameters
<sub id>
The identifier of the subroutine.
<parameter>
A formal parameter; can be a variable id, or an @<name>. A variable must be a simple variable or an entire array; individual array elements and substrings cannot be specified. To specify an array, use <array id>(*).
This allows the parameter to represent an array of any size, and with any number of dimensions. Variables can be either numeric or string. The subroutine can have up to 31 formal parameters.
Example
  sub Average (Type$, Values(*), Results(*), High, Low, @Printer)
     ! statements to manipulate data
  subexit \ subend
The preceding sub statement identifies a subroutine named Average, and its formal parameters. When this subroutine is called, the call statement will pass six parameters, to match those of the sub statement. The first must be a string, the second and third must be numeric arrays (they can have any size and number of dimensions), the fourth and fifth must be numeric variables or values, and the last parameter must be an @<name>.
It is not possible from the information given here to tell which parameters represent values passed to the subroutine, and which represent the locations to which the subroutine will send its final results. The logic of the calling program and the subroutine would determine that; the parameters passed must be of the same type as the formal parameters and must be logically consistent.
General Information
Arrays in the subroutine's formal parameter list cannot be dimensioned (dim statement). This is because a formal parameter is nothing more than a name to be used to temporarily identify the existing parameter passed to it. In this case the passed parameter is an array that has already been dimensioned in the environment of the program which called the subroutine.
Any arrays which are simply local to the subroutine (i.e., are used in the subroutine but do not appear in its formal parameter list, and are not global), must be dimensioned in the subroutine. They will not exist after the exit from the subroutine.
Any arrays to be declared as global in the subroutine must have been dimensioned in the main program before the subroutine is called. However, if a simple variable (e.g., A$, B) which does not yet exist is declared global in the subroutine, then that variable will exist in the main program.
