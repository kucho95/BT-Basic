bidirectional (VCL)
Title: BIDIRECTIONAL DEVICE‑PINS
The bidirectional statements appear in the Declaration section of the test to indicate which groups of pins are bidirectional. Each bidirectional pin has a separate driver and receiver assigned to it. In each vector, the group of pins is then declared as either all drivers or all receivers, but not both.
Mux systems only: The same group cannot be declared in a bidirectional function and in a bidirectional formatted function in the same test.
See also the inputs and outputs statements.
Syntax
  bidirectional <group id>
  bidirectional <group id>,<group id>
  bidirectional <group id>,<group id>, . . . <group id>
     <group id> is a <label>
Parameters
<group id>
The identifier of a group of pins to be declared as bidirectional. The group must have been defined in an assign to function.
Examples
  ! in the Declaration section
  assign Data_2 to device "U1" pins 3, 4, 5
  assign Flag to device "U1" pins 11, 15
  assign Clk to device "U1" pins 26
  assign Data_1 to device "U1" pins 7, 8, 9
  assign Sync to device "U1" pins 19
  bidirectional Data_1, Data_2
  outputs Sync
  inputs Flag, Clk
General Information
In the Vector Definition section of the test, each vector which references a bidirectional group should declare the direction of the pins in that group as either drivers or receivers, using the drive and receive statements. If the direction is not specified in a vector, it defaults to receive. PCF vectors use different characters for drive and receive states.
Each bidirectional pin has a separate driver and receiver. Therefore, if a vector starts with an initialize‑to function, any bidirectional pins in the initializing vector keeps their same directions in the initialized vector.
All library tests containing bidirectional pins must contain information to enable the i3070 In-Circuit Test Software to disable those pins; see the description of the disable with function.
