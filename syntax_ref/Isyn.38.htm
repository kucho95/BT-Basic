ipg (BT-Basic)
Title: RUN IPG
The ipg function invokes the Integrated Program Generator (IPG).
The program generator uses information from the board.o, board_xy.o, standard library tests, and any custom library tests that you add.
The program generator writes:
• Pre-shorts tests such as potentiometer tests.
• The shorts file to be used by shorts and opens testing.
• The pins file to be used by CHEK-POINT.
• VTEP tests in the testjet file (Mux system) or vtep file (UnMux system).
• A discharge test to discharge capacitors on the board under test if needed.
• Analog in-circuit tests.
• Digital in-circuit and digital functional tests.
• ipg/summary and ipg/details files.
• The testorder file.
Unless you specify a directory path name, the program generator assumes the current directory.
Use the ipg from and the ipg on statements to execute the program generator on specified tests.
While IPG is running, all keys are ignored except the BREAK key.
Syntax
  ipg
  ipg <option list 1>
  ipg; <option list 2>
  ipg <option list 1>; <option list 2>
     <option list 1> can be:   <directory name>
                               <directory name>, <error variable>
                               <error variable>
        <directory name> is a <string expression>
        <error variable> is a <numeric variable>
     <option list 2> can be:   <item>
                               <item>, <item>
                               <item>, <item>, . . . , <item>
        <item> can be:   shorts
                         pins
                         testjet  ! Mux systems
                         vtep     ! UnMux systems
                         analog
                         digital
                         functional
                         discharge
                         mixed
                         analog powered
                        <window>
                        <wait>
                        <experience level>
                        <backup level>
           <window> can be:   window
                              nowindow
           <wait> can be:   wait
                            nowait
                            failwait
           <experience level> can be:   standard
                                        advanced
                                        expert
           <backup level> can be:   numbered
                                    unnumbered
                                    nobackup
Parameters
 
<option list 1>
Can be either the directory pathname, or an error variable, or both.
<option list 2>
A list of optional parameters that determine how the function works. If you do not specify any options in this list, all tests are generated or re-generated. The options are:
• shorts - Generate the shorts file.
• pins - Generate the pins file.
• testjet - Generate the testjet file (for VTEP tests on Mux systems)
• vtep - Generate the vtep file (for VTEP tests on UnMux systems)
• analog - Generate the analog in-circuit tests.
• digital - Generate the digital tests.
• functional - Generate the digital functional tests.
• discharge - Generate the discharge test.
• mixed - Generate the mixed tests.
• analog powered - Generate the analog powered tests.
<window>
Specifies whether or not a new window is automatically opened when the function is executed. Permissible values are:
• window - A new window is opened.
• nowindow - Suppresses the opening of a new window.
<wait>
Specifies how the command executes. Permissible values are:
• failwait - The function executes and, if a failure occurs, the results remain on the screen so you can examine them.
• nowait - The function executes and does not pause for you to examine the results.
• wait - The function executes and the results remain on the screen so you can examine them.
<experience level>
Sets the length (thoroughness) of the error messages the user receives and can also be used to restrict the user to a subset of the full system features. Permissible values are: standard, advanced, and expert.
<backup level>
Determines if the system stores an unchanged copy (a backup) of files before modifying them, and how the backup is stored. Permissible values are:
• nobackup - No file backup is made.
• numbered - Makes up to nine backups, each numbered sequentially with .#~, such as file.1~. Number one is the most recent backup. When more than nine backups occur, the oldest file is discarded, and the others are renumbered.
• unnumbered - A single backup is made. The backup file name is appended with a tilde (~); for example, file~.
Examples
  ipg "/boards/cpu_board",E    ! "/boards/cpu_board" is the test directory pathname.
                               ! E is the error variable.
  ipg; digital, unnumbered     ! Run IPG on the digital tests and make a single backup
                               ! of any files that get modified.
General Information
The Break key is used to stop program generation before it has completed.
The program generator is run automatically during test development.
