rinit (ANALOG) (BT-Basic)
Title: INITIALIZE A MEASUREMENT SERVER
The rinit statement initializes a measurement server. It usually is executed only once each time a testplan is loaded and run; i.e., only when nrun = 1.
The debug option is used to start the Keysight VEE instrument server in its debug mode. When you subsequently make an rcall to an Keysight VEE statement, it opens a debug window that contains that statement for debugging, using the Keysight VEE debugging tools. When you finish debugging, close the window to continue running the BT-Basic or analog program. When you specify the debug mode, use a timeout that is longer than the expected debug time for any one statement. If timeout occurs, it will not affect your ability to complete debugging the statement, but it will stop the testplan. (The debug option operates with Keysight VEE version 3.2 and later.)
Syntax
   rinit <server name>
   rinit <server name>; <service>
   rinit <server name>; <service>, <options>
      <server name> is a <string expression>
      <service> can be:   program <file id>
                          servicetype <service name>
                          program <file id>, servicetype <service name>
         <file id> and <service name> are <string expressions>
      <options> can be:   hostname <string expression>
                          debug
                          timeout <seconds>
                          hostname <string expression>, debug
                          hostname <string expression>, timeout <seconds>
                          hostname <string expression>, debug, timeout <seconds>
         <seconds> is a <numeric expression>
Parameters
 
<server name>
A string expression containing the unique name of a measurement server.
<file id>
The identifier of a file containing the programs or statements that are to be executed by rcall statements.
<service name>
The name of the software that makes calls to the server. For Keysight VEE, the name is (vee). If the <servicetype> parameter is omitted, it defaults to vee.
host name
Used in a networked system to specify the name of the system on which the measurement server is to run.
timeout
The number of seconds a call to the measurement server will wait before a timeout error occurs. Specifying a value for timeout affects both the initialization of the measurement server—i.e., the rinit statement itself can time out if the initialization takes too long—and any subsequent calls that appear in rcall statements. When no value is specified, timeout defaults to 30 seconds.
If the debug option is used, specify a timeout that is longer than the longest time it will take to debug any one of the instrument server’s statements.
Example
! Invoke VEE from the testplan.
rinit "vee";
program btgetenv$("I3070_ICT_ROOT") & "/boards/myboard/workfile.vee", servicetype "vee"
 
! Invoke VEE with a timeout that occurs if the measurement server fails to
! respond within 80 seconds. The service type defaults to "vee".
rinit "vee";
program btgetenv$("I3070_ICT_ROOT") & "/boards/myboard/workfile.vee", timeout 80
 
! Invoke VEE in debug mode; here, timeout is set to four minutes (240 seconds)
rinit "vee";
program btgetenv$("I3070_ICT_ROOT") & "/boards/myboard/workfile.vee", debug, timeout 240
General Information
Having each <server name> be unique is important only when more than one measurement server can run simultaneously. Because the board test system normally does not use more than one measurement server at a time, you can use any arbitrarily chosen name for <server name>; if you like, all of your board tests can even use the same name. For consistency, we typically use vee as the name of the measurement server.
String expressions, such as <server name> and <file id>, are passed by value. The subprogram being called cannot alter data in the BT-Basic environment when data is passed by value.
