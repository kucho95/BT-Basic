on error (BT-Basic)
Title: BRANCH ON ERROR
The on error function defines the program activity that will occur if an untrapped, run time error occurs (i.e., an error caused by a function which does not specify an error variable).
The function has three secondary keywords: goto, call, and recover.
• goto — if an error occurs, branches to a label which must be in the same environment as the on error function; if the error occurs in a different environment then the branch does not occur.
• call — if an error occurs, calls a subroutine. After the exit from that subroutine, the program resumes with the first function on the line which was being executed when the error occurred—this applies regardless of the number of statements on the line, or which function was being executed when the error occurred. (Note that this differs from the standard subroutine call, which resumes execution with the function following the subroutine call.)
The call enables you to execute a subroutine to modify some variables and then automatically execute the line again, but with the modified data.
• recover — if an error occurs, branches to a label which can be in the same environment as the on error function or in a higher environment.
If the on error recover is in the main program, the destination line must also be in the main program. Unless temporarily overridden, this recover is always in effect. If the error occurs while a subroutine is being executed, program execution branches to the line in the main program, no matter how many subroutine nesting levels are currently active.
If the on error recover is in a subroutine, the destination line can be either in that subroutine or in the main program. When the function is executed, it determines the destination line by first searching the subroutine for the label and then, if not successful, by searching the main program. This recover is in effect only while the subroutine which contains it is being executed; this includes execution of any nested subroutines called by that subroutine.
Regardless of the type of branch or call, the on error activity is cancelled by an off error, or another on error function, or by the run function. An on error function executed in a lower environment is no longer active when the program returns to a higher environment. If an active on error is cancelled or overriden in a lower environment, then it will be automatically reinstated when the program returns to the environment in which it was active.
Syntax
  on error goto <line id>
  on error call <sub id>
  on error recover <line id>
     <line id> and <sub id> are <label>'s
Parameters
 
<line id>
The label at the beginning of the line where program execution is to resume (see the definitions of <label> and <line>).
• For a goto, the function, the referenced line, and the error must all be in the same environment.
• For a recover, the referenced line must be in the same environment as the function, or in the main program; if the line label is in both, the function selects the line in its own environment.
<sub id>
The identifier of the subroutine to be called.
Example
  on error goto Message
     . . .
  Message:
     print "Error "; errn; "on line "; errl
  goto Next_test
