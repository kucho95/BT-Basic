input using (BT-Basic)
Title: INPUT IMAGED DATA
The input using function is the same as the input function except that input using enables the input data to be image‑formatted. Data is input sequentially from the default input device, which is established by a keyboard is function.
The specifications which format and interpret the input data are referenced by means of the function's <image data> parameter. This parameter can itself contain the formatting specifications, or it can reference an image function which contains the specifications. The <variable list> contains the identifiers of the variables where the input data is to be stored.
As with the input function, the input data items are assigned, in the order in which they are input, to the variables listed in the function. The data, as formatted by the image specifications, must correspond item for item to the types (numeric or string) of the listed variables. Also, there must be sufficient data to fill all of the listed variables.
Manual input, i.e., from the workstation keyboard, is not normally used with image‑formatting, so a new default (device or file) must usually be established. The input using function accesses the data sequentially, starting at the first record. Only one record is read unless the image <line spec> (/) is used to enable the record boundary to be crossed. If all of the input variables have been satisfied before the end of the current record has been reached, then the data continues to be read, until the EOR (End Of Record) is read. However, this data is discarded. If the input is from an GPIB or RS‑232 device and the image function contains an inhibit‑EOL spec (#), reading stops as soon as sufficient bytes of data are read to satisfy the input variables.
As data is read, the system tracks its current read position by moving a pointer through the data. Unless you close the data source, the next access to that data starts at the current position of the pointer, i.e., at the beginning of the next record. If you wish to skip over one or more records you can do so by omitting the variable list from the input using function. One record is skipped, unless the image specification <line spec> is used to skip more than one record. The default file or device must be closed (another default designated) to return to the first record.
The following rules apply to the input data:
1 Each item of data must be the same type (numeric or string) as the variable to which it is to be assigned.
2 Numbers must contain only valid characters, in the proper order.
3 An input string cannot be longer than the dimensioned length of the variable to which it is assigned. After the input, the actual length of the variable is the same as the length of the string assigned to it. (The standard rules for assigning a string to a substring also apply.)
4 Delimiters (commas, etc.) in the input are ignored. The image specifications determine the start and end of each data item.
5 Input data can cross record boundaries, but an individual item cannot. Only one record is read, unless an image specification specifies otherwise.
6 Sufficient data must be input to fill all of the variables in the variable list. At the end of the input, an end‑of‑input is required unless an inhibit EOL (#‑spec) is included in the image specifications (the inhibit can be used only with GPIB or RS‑232 devices).
Syntax
  input using <image data>
  input using <image data>;<variable list>
     <image data> can be:   <image id>
                            <image specifications>
           <image id> is a <label>
           <image specifications> is a <string expression>
     <variable list> can be:   <variable>
                               <variable>,<variable>
                               <variable>,<variable>, . . . <variable>
           <variable> can be numeric or string
              [Use <array id>(*) to specify a complete array]
Parameters
<image id>
The identifier of the image function containing the specifications to be used to format the input data.
<image specifications>
The list of specifications to be used to format the input data. Refer to the image function for a complete description of the specifications.
<variable list>
The identifiers of the variables to which the input data are to be assigned. Any type of variable, including substrings, can appear in the list. If a complete array is specified, sufficient data must be supplied to fill all elements in that array.
If the variable list is omitted, the read pointer advances one or more records, as determined by the image specifications. The data skipped during the advance is ignored.
Examples
  L1: image dd.dd, sd.de, z.d
  input using L1; A, B, C
     !                                           A       B      C
     ! user inputs    ‑1.42+4.234  2.1         ‑1.42   4.234   2.1
  input using "dd.dd, sd.de, z.d"; A, B, C
     ! equivalent to the two statements above
  F$ = "12a, 6d"
  input using F$; Name$, ID_number
  L2: image 10a, 30(ddd), 30(sd.dddE)
  input using L2; Board$, Test(*), R_values(*)
     ! input to arrays
 
 
 
Refer to the description of the image function for examples showing how the image specifications format the input data.
General Information
Data entered from the keyboard is checked for errors, such as entering a string where a number is required, and can be corrected (edited) immediately, while erroneous data input from a device or file can generate an error and cause your program to abort.
