connect (CONFIGURATION)
Title: IDENTIFY A FUNCTIONAL PORT, ACCESS PORT, BALANCED PORT, OR EXTERNAL DEVICE
The connect function defines the identifiers for:
• a functional port
• an access port (AccessPlus Card)
• a balanced port (Utility Card)
• an external device (Utility Card)
This function appears within a module configuration block defined by module and end module statements in either the standard configuration file or in board configuration files; it must not appear in the testhead configuration file.
• When a connect function is associated with a balanced port, it must be preceded by a balanced ports function that declares the balanced ports for the Utility Card being used; see the description of the balanced ports function for details.
• When a connect function is associated with an external device, it must be preceded by an external devices function that declares the external devices connected to the Utility Card being used; see the description of the external devices function for details.
• (Mux systems only) When a connect function is associated with an access port, it must be preceded by an access ports function that declares the access ports for the AccessPlus Card being used; see the description of the access ports function for details.
Syntax
Functional port
  connect <instrument id> signal to <functional port id>
  connect <instrument id> trigger to <functional port id>
     <instrument id> is a <string constant>
     <functional port id> is ext<integer>
Access port (AccessPlus Card on Mux systems)
  connect <instrument id> access to <access port id>
     <instrument id> is a <string constant>
     <access port id> is acc<integer>
Balanced port (Utility Card)
  connect <instrument id> balanced to <balanced port id>
     <instrument id> is a <string constant>
     <balanced port id> is bp<integer>
External devices (Utility Card)
System config
connect "<device_name>" external to <xd_range>
Board config
connect "<device_name>" external to <xd_range> library "<dll_name>"
 
    <device_name> is a string (max 32 characters)
    <xd_range> can be: <xd_id>
                       <xd_id>, <xd_id>
                       <xd_id> to <xd_id>
        <xd_id> is xd<integer>
    <dll_name> is a string (max 32 characters; in board config only)
Parameters
<instrument id>
The name of an instrument connected to a functional port, access port, or balanced port. This can be up to 32 characters. The instrument name must be unique across all access port and balanced port devices in all the modules.
<functional port id>
The identifier of the functional port (ext1 to ext8).
<access port id>
The identifier of the access port (acc1 to acc18).
<balanced port id>
The identifier of the balanced port (bp1 to bp8). See Table C-7.
<device_name>
The name of the external device (maximum 32 characters).
<xd_id>
The identifier for the Utility Card slot where the device is connected (xd1 to xd12). See Table C-8.
<dll_name>
The name of the DLL that controls the external device (board config only).

Examples
Functional ports in board config
  module 3
     cards 1 asru n revision
     cards 2 to 5 hybrid high accuracy double density
     cards 6 control xtpb
     cards 7, 9 to 10 hybrid high accuracy double density
     supplies 1 to 4
     ports ext1, ext2
     connect "Digital_Scope" signal to ext1
     connect "Digital_Scope" trigger to ext2
  end module
External devices in board config
  module 3
  ...
     external devices xd1 to xd3 on card 10
     connect "flash" external to xd1 library "ABC.dll"
     connect "IC" external to xd2 to xd3 library "ic.dll"
  ...
  end module
General Information
The trigger statement controls the triggering (when a signal is measured) for analog functional tests while the signal statement controls the signal (what you want to measure) for analog functional tests. See the description of trigger (ANALOG) for more detail.
