display device (DEBUG)
Title: DISPLAY PIN DATA FOR A DEVICE
The display device function runs the test and displays the pin states either for all pins in the test currently being debugged, or for selected pins.
The function’s <response code> parameter specifies the type of data to be displayed, as listed next (actual states are displayed in green, expected states in white, and failed states in red):
• No parameter: actual states on receivers and bidirectional nodes (for drive and receive); expected states on drivers.
• a (actual): actual states on receivers and bidirectional nodes (for drive and receive); for the drivers, the user is prompted to place the probe to see the actual states.
• e (expected): expected states on all nodes (drivers, receivers and bidirectional nodes)—does not run the test.
• f (failed): same as e but runs the test; where a failure occurs, the expected state is highlighted in red.
• s (setups): lists the pin channel setups to the printer is device. The listing indicates whether the channel is driving or receiving, the events (FCLKs) in the machine vectors on which the channel is strobed, what the offsets are (if any), and the high and low driver or receiver voltages on that channel.
• v (vector drive/receive status): shows the direction, for each vector, of bidirectional pins—displays a series of D's (drive), R's (receive) and spaces (X or Z).
Syntax
  display device
  display device <response code>
  display device <response code><space><display line>
  display device <device spec>
  display device <device spec><space><response code>
  display device <device spec><space><response code><space><display line>
     <device spec> can be:   <designator>
                             <designator> pins <pin list>
        <designator> is a <string expression>
        <pin list> can be:   <pin id>
                             <pin id>,<pin id>
                             <pin id>,<pin id>, . . . <pin id>
           <pin id> can be:   <numeric expression>
                              <string expression>
     <response code> can be:   a
                               e
                               f
                               s
                               v
     <display line> is a <numeric expression>
Parameters
 
<device name>
The name of the device whose data is to be displayed. If no device is specified, data is displayed for the device or circuit currently being debugged.
<pin id>
The identifier of a pin to display. If no pins are specified, all pins of the device are displayed.
<response code>
Specifies the type of data to display; if not specified, the default types are displayed (see the introductory text above for details):
• a – actual
• e – expected
• f – failed
• s – setups for the pin channels
• v – vector drive/receive status
<display line>
The line number to start the display. If not specified, the display starts at line 1.
Examples
  display device e             ! display expected states for current device
  display device "u181"        ! display data for all pins of U181 - actual states on
                               ! receivers and bidirectional pins, and expected states
                               ! on drivers
  display device "u181" pins 4, 7, "clk"     ! display data for specified pins
  display device "u29" f                     ! display failed data
  display device "ctr1" e 12           ! display expected data, starting at line 12
                                       ! for a bidirectional pin:
     display device "u181" pins 6      ! display actual waveform
     display device "u181" pins 6 v    ! display directions
General Information
If the device designator is not included in the function, display device executes the test for the first device that it finds named in the current debug object. If the first device named is not the device being tested (perhaps it is another device which is to be disabled), an error occurs because debug tries to run the wrong test. To avoid this, include the name of the required device in the display device function.
