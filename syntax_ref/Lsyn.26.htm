log board (BT-Basic)
Title: LOG RECORD FOR A BATCH OF BOARDS
The log board function generates an @BATCH log record for the PC board under test. The log record contains information needed by Pushbutton Q-STATS or (optional) Q-STATS II to produce SQC reports.
Syntax
  log board <parameters>
  log board external <parameters>
  <parameters> are:   <UUT_Type>
                      <ProcStep>
                      <BatchID>
                      <Operator>
                      <UUT_TypeRev>
                      <TestplanID>
                      <TestplanRev>
                      <ParentPanelType>
                      <ParentPanelTypeRev>
                      <Version_Label>
     All <parameters> are <string expressions>
Parameters
<UUT_Type>
A code that identifies the type of board being tested, or the type of panel (when testing a multi‑board panel).
<ProcStep>
A code that identifies at which step in the production process the boards are being tested.
<BatchID>
A unique identifier that refers to a specific group of boards being tested.
<Operator>
A string that contains the name (or other identifier) of the test operator.
<UUT_TypeRev>
A code that identifies the revision of UUT_Type, which may be the revision of a board or of a multi‑board panel.
<TestplanID>
A string that identifies a specific testplan.
<TestplanRev>
A string that contains the testplan revision.
<ParentPanelType>
An optional parameter that identifies the type of panel that contains the board—i.e., you can think of a multi‑board panel as the parent of a specific board on that panel. <ParentPanelType> should have the same value as the UUT_Type parameter specified in the log board function for the panel. This parameter is not used for non‑panelized boards or for the panel itself.
<ParentPanelTypeRev>
An optional parameter that identifies the revision of the type of panel that contains the board. This parameter is not used for non‑panelized boards or for the panel itself.
<Version_Label>
An optional parameter that identifies the board version for Multiple Board Versions.
Examples
     ! When testing a non‑panelized board:
     !
  UUT$ = "VPC123" | PS$ = "btest" | B$ = "datetime$
  TP$ = BT$ | UUT_Rev$ = "revA"
  input "Enter Operator ID", O$
  log board UUT$, PS$, B$, O$, "", TP$, TPR$
     ! When testing a multi‑board panel:
     !
  UUT$ = "VPC123" | PS$ = "btest" | B$ = "datetime$
  TP$ = BT$ | UUT_Rev$ = "revA"
  Panel$ = "123" | PanelRev$ = "revB"
  input "Enter Operator ID", O$
  log board UUT$, PS$, B$, O$, "", TP$, TPR$, Panel$, PanelRev$
General Information
The current log level (set by a log level is function) must be board, or higher, for this record to be generated.
When using multiple board states (board number is function) to test a multi‑board panel, the @BATCH log record produced by the log board function is sent to the log buffer for the current board.
