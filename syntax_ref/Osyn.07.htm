on break (BT-Basic)
Title: BRANCH ON BREAK
The on break function defines the program activity that will occur if the operator subsequently generates a trappable break (see the syntax for Break Key).
The function has three secondary keywords: goto, call, and recover.
• goto — if a break occurs, branches to a label which must be in the same environment as the on break function; if the break occurs in a different environment then the branch does not occur.
• call — if a break occurs, calls a subroutine. After the exit from that subroutine, the program resumes with the first function on the line which was being executed when the break occurred—this applies regardless of the number of statements on the line, or which function was being executed when the break occurred. (Note that this differs from the standard subroutine call, which resumes execution with the function following the subroutine call.)
The call enables you to execute a subroutine to modify some variables and then automatically execute the line again, but with the modified data.
• recover — if a break occurs, branches to a label which can be in the same environment as the on break function or in a higher environment.
If the on break recover is in the main program, the destination line must also be in the main program. Unless temporarily overridden, this recover is always in effect. If the break occurs while a subroutine is being executed, program execution branches to the line in the main program, no matter how many subroutine nesting levels are currently active.
If the on break recover is in a subroutine, the destination line can be either in that subroutine or in the main program. When the function is executed, it determines the destination line by first searching the subroutine for the label and then, if not successful, by searching the main program. This recover is in effect only while the subroutine which contains it is being executed; this includes execution of any nested subroutines called by that subroutine.
Regardless of the type of branch or call, the on break activity is cancelled by an off break, or another on break function, or by the run function. An on break function executed in a lower environment is no longer active when the program returns to a higher environment. If an active on break is cancelled or overriden in a lower environment, then it will be automatically reinstated when the program returns to the environment in which it was active.
Syntax
  on break goto <line id>
  on break call <sub id>
  on break recover <line id>
     <line id> & <sub id> are <label>'s
Parameters
 
<line id>
The label at the beginning of the line where program execution is to resume (see the definitions of <label> and <line>).
• For a goto, the function, the referenced line, and the break must all be in the same environment.
• For a recover, the referenced line must be in the same environment as the function, or in the main program; if the line label is in both, the function selects the line in its own environment.
<sub id>
The identifier of the subroutine to be called.
Example
  on break goto Message
     . . .
  Message:
     print "Operator pressed Break at "; time$
  goto Next_test
