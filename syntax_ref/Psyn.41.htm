probe report (BT-Basic)
Title: ENABLE WORST PROBE DATA GENERATION
The probe report statement directs the system to start or stop generating failure data for probes associated with shorts/opens, analog in-circuit, and VTEP test failures. The generated failure data is used to construct the content for the Worst Probe Report display area in the operator interface.
The information displayed includes the fixture probe number and the number of times the probe was listed in the probe failure data file. This information provides the ability to easily identify non-optimal probes or probing locations that may be responsible for failing tests.
The probe report on statement is inserted after the load board statement by testmain. This is to enhance worst probe reporting whenever the testplan is restarted.
Syntax
   probe report on
   probe report off
Parameters
(none)
Examples
   if nrun = 1 then
      print First_Run$
      probe report on        ! Enable generation of probe failure data and
      load board             ! loading of fixture object information
      .
      .
      test "analog/r201"
   probe report off          ! Disable generation of probe failure data
      test "analog/r202"
   probe report on           ! Enable generation of probe failure data
      .
      .
General Information
When the probe report on statement is issued prior to the load board statement, the load board statement will automatically create the file WorstProbeReport/probe_report.txt in the board test directory as the storage location for probe failure data.
The probe failure data generated by the use of the probe report statement is not included in and does not change the format of the standard log records generated by the test system for use by Pushbutton Q-STATS.
Refer to Release to Production for details on enabling the Worst Probe Report display.
