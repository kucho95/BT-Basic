copy over/copy to (BT-Basic)
Title: COPY OVER AN EXISTING FILE AND COPY TO A NEW FILE
The copy over and copy to statements are used to copy between files or devices on the test system, to copy a file to the local line printer or plotter, and to copy between files on different systems in a network. Copying files across a network requires that the networked systems be properly configured to communicate with one another; i.e., remote file system(s) you need to access must be mounted to your local file system.
The copy over function copies the contents of a file or a device (the source) over an existing file or device (the destination). The source remains unchanged. If the destination is a file that does not exist, copy over creates it; if the destination is a file that does exist, its original contents are lost (overwritten). If the source and destination files are of different types—e.g., a BT-Basic program is copied over a VCL program, or ASCII‑source code is copied over object code—then the destination file is changed to the same type as the source file.
The copy to function copies only to files that do not already exist; an attempt to copy to an existing file generates an error. copy to creates a new file (the destination) and then copies a file or device (the source) into it. The source remains unchanged. Unlike copy over, copy to does not copy to a device; an attempt to copy to a device generates an error.
Either function can copy multiple files; that is, the function can specify several source files. (Note, however, that a destination file cannot be used as a source.) Also, either function can copy a partial file by including first and/or last line numbers with the specified source file.
The following rules apply when copying multiple source files:
• If the multiple source files are of the same mode (text, basic, etc.), the resultant file is of that mode. Otherwise, it is of text mode.
• Multiple source files are copied in the order of their appearance, left to right, in the copy function.
If no line numbers are specified in the copy function, the entire file is copied. If line numbers are specified, the following rules apply:
• When first and/or last line numbers are included with the source file, then only the specified file lines are copied.
• If only a first line number is specified, the system copies from that line number to the end of the file. However, do not specify a line number that is beyond the end of the source file or an error results.
• If only a last line number is specified, the system copies from the beginning of the file to that (last) line number. If you specify a last line number that is beyond the end of the source file, the entire file is copied.
File copying over a network is similar to local copying, except that you must also specify which remote system is to be accessed. Because the networking information is simply added to the file id's, the general format of the statements—i.e., copy <file> over/to <file>—remains the same.
Syntax
  copy <source list> over <destination>
  copy <source list> over <destination>,<error variable>
  copy <source list> to <destination>
  copy <source list> to <destination>,<error variable>
     <error variable> is a <numeric variable>
     <destination> can be:   <file id>
                             lineprinter
                             plotter
     <source list> can be:   <source>
                             <source>;<source>
                             <source>;<source>; . . . <source>
           <source> can be:   <file id>
                              <file id>,<1st line #>
                              <file id>,<1st line #>,<last line #>
                              <file id>,,<last line #>
              <file id> is a <string expression>
              <1st line #> and <last line #> are <numeric expressions>
Parameters
 
<source>
The file or device whose contents are to be copied. The source is opened shared—i.e, other users have access to it—for the copy, and then closed.
<destination>
The file or device to which the copy is to be sent. The destination is opened exclusively and then closed after the copy.
If the copy is aborted (Break or stop) during execution, a newly‑created destination file is automatically unlinked. An existing destination file is closed partially written.
If <destination> is lineprinter, the contents of the file are printed on the local line printer.
If <destination> is plotter, the contents of the file are printed on the local plotter.
<file id>
The identifier of a file, which can represent a file on the disk or a device. If <file id> specifies a file, that file must be an ASCII file, not a binary (object code) file.
When networking, <file id> must be prefixed with the path to the remote system. By convention, the prefix is /sys followed by the name of the remote host; for example, /sys/alpha/<file id>.
<1st line #>
Numeric expression that delineates a partial file to be copied. Note that unless the numeric expressions used as line numbers evaluate to positive numbers, an error message is issued.
<last line #>
Numeric expression that delineates a partial file to be copied. Note that unless the numeric expressions used as line numbers evaluate to positive numbers, an error message is issued.
<error variable>
The identifier of an error variable
Examples
  ! Copy one file to another file (not networked)
     copy "test1" over "testnn"
  ! Copy multiple files into a single file (not networked)
     copy "File1"; "File2" over "File3"
  ! Copy part of a file to another file (not networked)
     copy "File1",5,10 over "File3"
     copy "text_file" over "example", Error ! Includes error variable
  ! Copy a file into a new file
     copy "/library/ttl/safeguard/parameters/sttl" to "sttl"
  ! Copy a local file to a remote system named "beta"
     copy "test_­­data" over "/sys/beta/records/tests
  ! Copy a file to the local line printer
     copy "test_data" over lineprinter
  ! Copy a file to the local plotter
     copy "probes.p" over plotter
General Information
If you use copy over with the intention of creating a new file, there is always the possibility that you copy over a file that you do not know exists, and that belongs to another test developer; use copy to when copying to a new file.
When copying with devices, the copy must make sense. For example, trying to copy an object file over a printer, or copying a printer over a file, results in an error.
