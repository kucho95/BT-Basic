log — statement (BT-Basic)
Title: GENERATE A USER‑DEFINED LOG RECORD
Use the log statement to generate user‑defined log records in free‑field format. User‑defined log records can duplicate existing log records, or they can be created from scratch for custom applications (which require custom routines to process the non-standard log records).
Operation of the log statement is similar to the operation of the print function, except that print prints to the default printer, and log prints to the log buffer.
 
 
Use the log using statement when the log record exceeds 80 characters, and the log data is used with Pushbutton Q-STATS or other log-data consumers.
Records greater than 80 characters are automatically broken into separate lines of 80 characters or less by the log statement, thus corrupting the log data and causing errors to occur with Pushbutton Q-STATS and other log-data consumers. To avoid this, use the log using statement whenever the output might exceed 80 characters.
Syntax
  log
  log <log list>
     <log list> can be:
        <item>
        <item><delimiter><item>
        <item><delimiter><item><delimiter> . . . <item>
           <item> can be:   <numeric expression>
                            <string expression>
                            <tab function>
           [If <expression> is an array, use <array id>(*)]
           <delimiter> can be:   ,  (comma)
                                 ;  (semicolon)
Parameters
 
<log list>
The list of data items to be output in free‑field format. A data item is output in a standard field if its delimiter is a comma, and it is output in a packed field if its delimiter is a semicolon. If the list has no items, a blank log record is output.
To output a complete array of data, use <array id>(*).
If the <item> is a tab function, the log position moves to the column indicated; the next field then starts in that column. If the column indicated is to the left of the current position, an EOL is output and the next field starts at the indicated column in the next record.
There is no difference between the comma and the semicolon used as the delimiter after a tab function; neither affects the format in this case.
Examples
  input "What is your name", Operator$
  log "{My_Record|‑‑ Operator: "; Operator$; " started at ";time$; "}"
General Information
These records are generated for all log levels except none. For imaged formatting, refer to the log using function.
When using multiple board states (board number is function) to test a multi‑board panel, the log statement sends log records to the log buffer for the current board.
