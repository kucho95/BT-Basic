homingloop (VCL)
Title: START HOMING LOOP
The homingloop function is used in the Vector Execution section of a device test to mark the start of a homing loop; the end homingloop function marks the end of the loop.
Homing is a process which enables a device to be brought from an unknown state to some known state; once the state of the device is known, actual testing can proceed. The statements in the loop are executed repetitively until the device reaches some predetermined state, at which time the exit is made from the loop.
The decision to exit the loop is made by a vector execution function which has the exit if pass keyword. If the actual received states for that vector match the expected states, the exit is made; otherwise, execution of the statements in the loop continue.
Twelve no‑op (no operation) vectors are executed after each exit if pass vector, unless the loop contains piped vectors (see the third example, below). If piped vectors are used, they determine the state of the device after the exit from the loop. Refer to The Pipe in Digital Testing, and to the description of piped (VCL) for more details.
There are two types of homingloops: uncounted and counted. The uncounted loop is time indeterministic; therefore, the VCL test which contains an uncounted loop requires a test time function for the SAFEGUARD safety analysis routines, otherwise the test is inhibited from running. If the loop fails to exit for any reason, it continues to run until a test timeout.
The counted loop has a <maximum> times parameter that can operate in either of two ways, depending on whether the test contains an enable loop counter function.
• If there is no enable loop counter in the test (or if the function is not valid), the <maximum> times parameter indicates to the safety analysis routines the maximum number of times the test is expected to run. This number is one of the parameters used in determining the timeout for the test. If the device fails to home for any reason, then, like the uncounted loop, the loop continues to run until test timeout.
• If there is a valid enable loop counter function, the homingloop becomes a true counted loop. The <maximum> times parameter indicates the maximum number of times the homingloop can run. If the loop runs that many times and fails to exit, the loop and the test stop, and a failure is recorded.
The following rules apply to homing loops:
1 Homing loops cannot be nested.
2 A subroutine call cannot be used in the loop; but a homing loop can be included in a subroutine.
3 Compression (CRC) cannot be used in the loop.
4 At least one of the vector execution statements (execute, preset counter or count) must have an exit if pass keyword.
5 The vector execution statements can use only the exit if pass and sync keywords.
6 A library program for a combinatorial device cannot contain a homing loop.
7 Statements which halt the test cannot be used; these are:
– delay for cooling
– halt
– pause
8 Fixed nodes must not exist in any vectors used within a homingloop unless they are specified as x (don’t care).
Syntax
  homingloop
  homingloop <maximum> times
     <maximum> is a <numeric constant>
Parameters
<maximum>
Maximum number of passes which the loop is expected to make. Any positive integer up to 216 – 1 (65535) can be specified.
Examples
  ! uncounted homing loop
        . . .
     homingloop
        execute Vec0
        execute Vec_Home exit if pass   ! determines the device's final states
        execute Vec0
        execute Vec1
     end homingloop
  ! a counted loop                      ! without "enable loop count" function
        . . .
     homingloop 8 times                 ! no more than 8 passes are expected
        execute Clock0
        execute Clock1 exit if pass
        execute Null_Clock
     end homingloop
  ! a true counted loop
     ! Declaration section of the test
        enable loop counter
           . . .
     ! Vector Execution section of the test
           . . .
        homingloop 8 times      ! test fails if loop fails to exit after 8 passes
           execute Clock0
           execute Clock1 exit if pass
           execute Null_Clock
        end homingloop
  ! uncounted homing loop, with four "piped" statements
        . . .
     homingloop
        execute Vec0
        execute Vec1 exit if pass
        execute Vec2 piped
        execute Vec3 piped
        execute Vec4 piped
        execute Vec_Home piped          ! determines the device's final states
        execute Vec_A
     end homingloop
