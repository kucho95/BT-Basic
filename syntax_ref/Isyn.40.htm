ipg on (BT-Basic)
Title: RUN IPG ON THE SPECIFIED TESTS
The ipg on function runs the Integrated Program Generator (IPG) on the specified tests. Use this function to run the program generator on a limited number (e.g. one to four) of the tests in your board directory.
To run the program generator on several, but not all, of the tests in your board directory, use the ipg from function. Refer to the ipg function description for details of IPG.
Unless you specify a directory path name, the program generator assumes the current directory.
While IPG is running, all keys are ignored except the Break key.
Syntax
  ipg on <device(s)>
  ipg on <device(s)>, <error variable>
  ipg on <device(s)>; <option list>
  ipg on <device(s)>, <error variable>; <option list>
  ipg <directory id> on <device(s)>
  ipg <directory id> on <device(s)>, <error variable>
  ipg <directory id> on <device(s)>; <option list>
  ipg <directory id> on <device(s)>, <error variable>; <option list>
     <device(s)> can be:   <device>
                           <device> <device>
                           <device> <device> . . . <device>
        <device> can be:   testjet  ! Mux systems
                           vtep     ! UnMux systems
                           <device id>
                           <board#>:<device id>
           <board#> is an <integer>
           <device id> is a <string expression>
     <directory id> is a <string expression>
     <error variable> is a <numeric variable>
     <option list> can be:   <item>
                             <item>, <item>
                             <item>, <item>, . . . , <item>
        <item> can be:   shorts
                         pins
                         discharge
                         <window>
                         <wait>
                         <experience level>
                         <backup level>
           <window> can be:   window
                              nowindow
           <wait> can be:   wait
                            nowait
                            failwait
           <experience level> can be:   standard
                                        advanced
                                        expert
           <backup level> can be:   numbered
                                    unnumbered
                                    nobackup
Parameters
 
testjet
Generate the testjet file for VTEP tests on Mux systems.
vtep
Generate the vtep file file for VTEP tests on UnMux systems.
<device id>
The device for which to develop a new test.
<board#>:<device id>
The device for which to develop a new test, for all boards on the panel that are of the same type as the board number specified (for PanelTest only).
<directory id>
The pathname of the board directory.
<option list>
A list of optional parameters that determine how the function works. The options are:
• shorts - Re-generate the shorts file in addition to the specified devices.
• pins - Re-generate the pins file in addition to the specified devices.
• discharge - Re-generate the discharge test in addition to the specified devices.
<window>
Specifies whether or not a new window is automatically opened when the function is executed. Permissible values are:
• window - A new window is opened.
• nowindow - Suppresses the opening of a new window.
<wait>
Specifies how the command executes. Permissible values are:
• failwait The function executes and, if a failure occurs, the results remain on the screen so you can examine them.
• nowait The function executes and does not pause for you to examine the results.
• wait The function executes and the results remain on the screen so you can examine them.
<experience level>
Sets the length (thoroughness) of the error messages the user receives and can also be used to restrict the user to a subset of the full system features. Permissible values are: standard, advanced, and expert.
<backup level>
Determines if the system stores an unchanged copy (a backup) of files before modifying them, and how the backup is stored. Permissible values are:
• nobackup No file backup is made.
• numbered Makes up to nine backups, each numbered sequentially with .#~, such as file.1~. Number one is the most recent backup. When more than nine backups occur, the oldest file is discarded, and the others are renumbered.
• unnumbered A single backup is made. The backup file name is appended with a tilde (~); for example, file~.
Examples
  ipg "/boards/cpu_board" on "U101"
       ! Run the program generator on U101 in "/boards/cpu_board".
  ipg on "R1" "U2"; nobackup
       ! Run the program generator on R1 and U2 and do not make
       ! a backup of any files.
General Information
The Break key is used to stop program generation before it has completed.
