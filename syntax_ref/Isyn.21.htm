initialize to (VCL)
Title: COPY A DEFINED VECTOR
The initialize to function is a typing aid that provides you with a quick way to write the statements for a new vector which is similar to a vector which has already been defined. To define the new vector, you use the initialize to function to reference the similar vector; then you change those parts of the new vector which are different. If used, initialize to must be used only once in any vector block and it must be the first function after the vector function. The initializing vector must precede the new vector in the Vector Definition section of the VCL test.
The initialize to function carries with it most of the data from the initializing vector: this includes all pin states, and the direction (drive or receive) assigned to any bidirectional pins and the timing set1, if any, used by the vector. However, counters are not transferred.
Each bidirectional pin has a separate driver and receiver assigned to it. Therefore, the initialize to function carries direction and state data either for the driver or for the receiver (as determined in the initializing vector), but not for both at the same time.
To change any of the data brought from the initializing vector, type a function containing the new data, remember, within a vector block, if two statements conflict, the later function always overrides the earlier one.
Initialized vectors are cumulative: i.e., a vector that was itself initialized can be used to initialize another vector, and so on.
 
1. Mux systems only.
Syntax
  initialize to <vector id>
     <vector id> is a <label>
Parameters
 
<vector id>
The identifier of the initializing vector. A vector with this identifier must have been defined earlier in the same VCL test.
Examples
In the following vector definitions, the resulting vectors are shown in the comments; the states shown in parentheses are the initial states brought from another vector.
  ! in the Declaration section
        . . . .
     assign Enable to pins 8
     assign Input to pins 2, 3, 4, 5
     assign Out1 to pins 10
     assign Out2 to pins 13
        . . . .
     inputs Enable, Input    ! drivers
     outputs Out2    ! receiver
     bidirectional Out1
        . . . .
  ! in the Vector Definition section
        . . . .
  vector  Init
     drive Out1                ! Out1 is a driver
     set Enable   to   "1"     ! Out2 is not included; it defaults to "X"
     set Input    to   "ZZZZ"  !
     set Out1     to   "0"     !
  end vector                   ! 1ZZZZ0X
  vector  E1
     initialize to Init        ! ( 1ZZZZ0X ) — Out1 is a driver
     set Input    to    "11ZZ"
     set Out1     to    "1"
  end vector                   ! 111ZZ1X
  vector  E2
     initialize to Init        ! ( 1ZZZZ0X ) — Out1 is a driver
     receive Out1              ! Out1 is a receiver; it defaults to "Z"
     set Input    to   "ZZ11"
     set Out2     to   "0"
  end vector                   ! 1ZZ11Z0
  vector  Test
     initialize to E1          ! ( 111ZZ1X ) — Out1 is a driver
     set Input    to   "kk11"
     set Out2     to   "0"
  end vector                   ! 1kk1110
General Information
Carrying states from one vector to another by the initialize to function is significantly different from using keeps (K) and toggles (T). K and T take effect at execution time and rely for their states on the vector which has just been executed. Because of this, if you are writing vectors with K’s an T's, then you have to consider the possibility of the program generators discarding a critical vector because of a topology conflict.
On the other hand, initialize to takes effect as soon as the test is compiled, so you do not have to worry about the program generators removing a vector which you used to initialize another vector. Once the test has been compiled, there is nothing in the compiled code to distinguish between vectors that were generated with the initialize to function and vectors in which all of the statements were typed.
