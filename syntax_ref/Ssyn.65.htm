status (BT-Basic)
Title: READ THE STATUS OF AN RS-232 PORT
The status statement reads the status of a file or character device used for RS‑232 operations. The status information is stored in registers whose values are written by a control statement and read by a status statement. When a status statement is executed, it returns the status information to one or more variables specified in the statement’s variable list.
Syntax
  status <source>; <numeric variable list>
  status <source>, <register #>; <numeric variable list>
     <source> can be:
        @<name>
        <file id>
           <name> is a <label>
           <file id> is a <string expression>
     <register #> is a <numeric expression>
     <numeric variable list> can be:
        <numeric variable>
        <numeric variable>, <numeric variable>
        <numeric variable>, <numeric variable>, . . . <numeric variable>
Parameters
 
<source>
The file or character device to be interrogated; you cannot use the status statement to interrogate block devices.
<register #>
An integer from 1 to 13, or 17, that identifies which control register to read, where each register controls some aspect of serial data transfer.
The values in the registers are passed to however many <numeric variables> are specified in the <numericvariable list>, beginning with the first <register #> specified; see Example below. If no value is specified for <register #>, the value defaults to 1.
The register numbers and their statements are given in Table S-5. These registers correspond to the standard HP-UX termio definition.
<numeric variable list>
The list of variables where the returned register values are to be stored. Since there are 14 registers readable by the status statement (1-13 and 17), this list must not contain more than 14 variables.
 
Table S-5 Registers
Register #
Statement
1
Specifies basic terminal input control; corresponds to c_iflag in termio.
2
Specifies system treatment of output; corresponds to c_oflag in termio.
3
Specifies the hardware control of the terminal; corresponds to c_cflag in termio.
4
Specifies how the line discipline should control terminal statements; corresponds to c_lflag in termio.
5
Specifies the line discipline; corresponds to c_line in termio.
6
Defines which special character generates an interrupt signal; defaults to DEL (ASCII 16).
7
Defines which special character generates a quit signal; defaults to FS (ASCII 28).
8
Defines which special character erases the preceding character; defaults to # (ASCII 35).
9
Defines which special character deletes an entire line (as delimited by a NL, EOF, or EOL character); defaults to @ (ASCII 64).
10
Defines which special character denotes an end of file (EOF); defaults to EOT (^D or ASCII 4).
11
Defines which special character denotes an end of line (EOL); defaults to NUL (ASCII 0).
12
(reserved)
13
Defines the SWTCH character; defaults to NUL (ASCII 0).
17
This register cannot be written to. A status statement that specifies this register will return the number of characters immediately readable from the terminal device; corresponds to the ioctl FIONREAD command in termio.
Example
  assign @Terminal to "/dev/tty3"        ! Associate @Terminal with device tty3
  control @Terminal, 3; oti ("1000")     ! Set up the RS-232 port; 1200 baud
  status @Terminal, 3; Status            ! Read the status of the RS-232 port
  print ito$ (Status)                    ! Print 1000
  status @RS232; A, B, C, D              ! Return status of registers 1, 2, 3, 4
  status @RS232, 8; A, B, C              ! Return status of registers 8, 9, 10
General Information
Use the control statement to write values to the registers that status reads.
Note that there are actually 17 registers that the control statement can write to. However, the status statement can only return the status of 14 registers (1 through 13, and 17) of the 17 registers. For information about the other registers, see the description of the control statement.
