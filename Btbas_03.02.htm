Introduction to Program Control Structures
The BT-Basic language has several branching statements and program structures. These give you considerable flexibility in arranging the order in which program lines will be executed. In addition, use of the structures enhances readability of the program: each structure has its own set of statements, so it is a simple matter to recognize the structure in the program listing and see what that part of the program does.
Table 4-1 defines terms used in this chapter.
 
Table 4-1 Program control structures
Term
Definition
branching
Not executing the next statement in the program but, instead, going to some other point in the program and continuing execution with the statements encountered there. A branch is unconditional if the program is given no choice and must make the branch; the branch is conditional if the program itself can make the decision whether or not to branch.
looping
Executing a group of statements one or more times. The number of times a loop is repeated can be determined either by counting the number of executions and then exiting the loop once the required count is reached, or by some other decision making process, such as the result of a calculation exceeding a predetermined value.
subprogram
A set of statements which does not reside in the main program. A subprogram is invoked (or called) from the main program and executed; execution then returns to the calling point in the main program and continues. It is also possible for subprograms to be nested, that is, for one subprogram to call another. In this case, the call and the return to the calling point occur within the subprograms. In BT-Basic, subprograms refers to subroutines and user‑definable functions.
BT-Basic has several different types of branching statements (see Table 4-2), both conditional and unconditional. The goto statement makes an unconditional branch. The computed branch, the on statement, is also unconditional, but it has a list of options from which it chooses where to branch. The on break and on error statements are used for error trapping; they cause delayed branches, that is, they do not branch when executed, but instead they define conditions that will cause the program to branch if those conditions occur at any time later in the program. Since the conditions might, or might not, occur, the delayed branches are classified as conditional.
BT-Basic has two program structures which enable looping and one program structure that enables conditional branching: these are the the loop structure (the uncounted loop), the for/next structure (the counted loop), and the if structure (a conditional branch). Each structure has several control statements associated with it.
The subprograms in BT-Basic are the subroutines and the user‑definable functions. From the point of view of the calling program, a subroutine is called and executed as if it were a single statement, regardless of how many statements the subroutine actually contains. A user‑definable function appears to be simply a part of an expression, just like any of the standard, mathematical functions (for example: sqr or cos). The difference between the two types of functions is that the user‑definable functions are defined by the programmer, while the standard functions are a fixed part of the system language.
