Inputting Data in Free-Field Format
When an enter or input statement is encountered the system either reads data from the specified source, or, if the input is to be from the keyboard, it waits for you to supply the data. From the system's point of view, reading data from the keyboard or any other source is the same thing, except that input from the keyboard is slower. So if you understand the input rules for the keyboard, you can apply the same rules to other devices—reading a file from a disk drive, for example.
During the input, each data item is stored into an appropriate numeric or string variable which is specified in the statement's variable list. The incoming data items must be separated from each other by delimiters, as described in the reference description above. The data items are stored, in the same order that they are input, into the variables in the order that they appear in the variable list, that is, from left to right. Each item must be the same type, numeric or string, as the variable to which it is to be assigned.
When you input numbers from the keyboard, you can either type one number on a line, with a Return after each number, or you can type several numbers on a line and then give the Return. You can input just one line or several lines, with each line corresponding to a record from a device or file. Here are some examples.
   input "Type three numbers", A, B, C
In response to the message—i.e., the text from the statement—displayed on the terminal screen, the user could respond by typing the numbers on one line:
   3025,  9012,     56
Or, say, on two lines:
   3025    9012
  56
Notice that the spacing is not critical and either a space or a comma can be used as a delimiter. After the input, the listed variables contain the three numbers:
   print A, B, C    ! prints  3025 9012 56
If a null input is made to a variable, then that variable retains its original contents. For example, if the above statement is executed a second time, you might want to change only the third number, in variable C. In this case a null input—a comma only—can be made for any variables which are not to be changed:
   ,,82
Printing the variables shows that, in this case, only the last one changed:
   print A, B,C   ! prints    3025 9012 82
When inputting strings from the keyboard, the rule of thumb is always to input only one string on each line. If you do not, then you must carefully count the characters so as to match the dimensioned lengths of the input variables. While you will probably have to arrange inputs from files and devices so that they match the lengths of the variables, it is not practical when entering data from the keyboard.
For example, consider this statement in Example 5-4.
Example 5-4 Example of inputting strings from the keyboard
   dim Name$[25], Title$[30]
   input "Type your Name and Job Title", Name$, Title$
 
Provided that you input your name and title on separate lines, you need not be concerned about the length of the variable—that is, as long as your name is not more than twenty‑five letters and your title more than thirty. However, if you make both inputs at once then you must count the characters:
   Peter Smith                Supervisor
   <‑‑‑‑‑‑--- 25 spaces ‑‑‑‑‑>
It does not matter if you leave extra spaces — they will be ignored. But Example 5-5 shows what can happen if you do not leave the proper number of spaces.
Example 5-5 Example of not leaving the proper number of spaces
   ! Peter Smith        Supervisor
   print Name$; len(Name$)       ! prints Peter SmithSuperv 25
   print Title$; len(Title$)     ! prints isor 4
 
The same rules apply if you are inputting both strings and numbers as in Example 5-6.
Example 5-6 Example of inputting both strings and numbers
   dim Name$[40]
   input "Type your Number, Name and Age", Num, Name$, Age
      ! Typed:  21099,   Peter Smith                         28
   len(Name$)       ! returns 40 ‑‑ the maximum length
 
But if you had typed:
   21099,     Peter Smith
   28
then:
   len(Name$)      ! returns    11
because the Return truncated any trailing spaces in the string.
